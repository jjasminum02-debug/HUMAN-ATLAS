## 구현한 범위

학습 `/`에서 부위마다 key가 달라져 재생성되던 GLBViewer를 persistent `WholeBodyViewer`와 `AnatomySceneController`로 교체했다. 하나의 `AnatomySceneRoot`, WebGLRenderer/canvas, camera/OrbitControls, 조명, 재질 정책, 자원 queue와 update loop가 부위·선택·레이어·전체 보기를 처리한다. `/review`의 기존 제작용 viewer 및 사용자 draft 저장소는 수정하지 않았다.

T70 parent 493개에 T71의 신규 9개와 T72의 신규 11개를 **sibling으로 합산**했다. T72의 parent 사본으로 T71을 덮어쓰지 않았다. 입력 14개 GLB의 두 공유 source 중복 참조는 T70 suppression 계약대로 제거해 513개 고유 ELEMENT ID를 유지한다. 이는 근육 513개 또는 전신 분모가 아니다.

원본 GLB/OBJ·source ID/hash/좌표/역사 manifest를 바꾸지 않고 27개 지역·레이어 묶음으로 accessor bytes를 재포장했다. 다중 지역 소속은 같은 source node를 재사용한다. 지역과 뼈/근육 레이어에 필요한 묶음만 동시 2개까지 요청하며, 완료한 묶음은 이 장면의 manifest 한도 내에서 재사용한다. 취소 후 도착한 parse 결과와 종료 후 도착한 자원은 폐기한다. 부분 실패는 기존 장면을 보존하고 명시적 재시도를 제공한다. context-loss/restoration도 같은 root/canvas/camera/선택을 유지한다.

부위 이동·화면 맞춤·전체 보기는 명시적 camera 명령이다. 일반 선택/레이어 토글/새 파일 도착/재시도는 camera를 재설정하지 않는다. renderer가 소유하는 `addUpdate()` interface를 두어 향후 motion controller가 별도 RAF나 viewport 없이 같은 loop를 사용할 수 있도록 했다. 실제 운동·수축·OpenSim 정합·신규 binding은 만들지 않았다.

T71/T72의 `learnerDefaultVisible=false`를 몰래 true로 바꾸지 않았다. opt-in은 로컬 source surface 문맥 보기이며 학습 선택·human review·공개 재배포 승인으로 승격하지 않는다. 기존 비복근 parent 선택은 catalog에 이미 연결된 두 part ID를 강조할 뿐 parent binding을 새로 만들지 않는다. 뼈 선택은 원본의 명시적 laterality를 이용해 기존 structure instance에 연결한다. 좌측 경로에서 우측 binding을 재사용해 강조하지 않는다.

공개 재배포 보류를 지키기 위해 신규 cache는 Vite **로컬 개발 middleware만** 제공한다. allowlist와 SHA-256 검사를 적용했고 production build/preview에는 이 GLB와 QA entry를 넣지 않는다. 따라서 현 production build는 자산 제공 환경이 없으면 밝은 실패 안내와 재시도를 표시한다. 종아리 fallback이나 공개 asset URL로 대체하지 않는다. 현 checkout의 개발 모드 검증을 배포 가능한 앱 완성으로 해석하면 안 된다.

## 검증

- `unit-tests.txt`: 신규 정책/queue 검사와 기존 navigation/region-navigation/scene-lifecycle 회귀 **31/31 통과**. stale parse 폐기, 취소 후 같은 ID 재요청, 부분 실패 및 재시도, 종료 후 자원 도착, source-only/held 선택 금지, 잘못된 단위/ID 계약을 포함한다.
- `asset-verification.json`: **2,111 checks**, 513개 node/accessor payload hash 대조, 원본 metadata/geometry 보존. 모든 node 포함 triangle 수 2,554,836; 화면에 보이는 수와 구분한다.
- `repack.json`: 입력 세 manifest SHA, 27개 파생 GLB SHA, 513개 geometry payload SHA. GLB 총 64,784,624 bytes. 재실행 결과 동일; 원래 reduced 한 해상도를 분할한 것이며 해상도를 새로 만든 것이 아니다.
- `browser-lifecycle.json`: 실제 동결 GLB로 **12개 검증 통과**. 1회 HTTP 503을 주입한 부분 실패/복구와 실제 WebGL context loss/restore, 빠른 지역 전환, root/canvas 동일성, 선택/카메라 보존, disposal을 확인했다. 성공적인 로딩/그림은 합성 mesh가 아니다.
- 해당 로컬 브라우저 계측: source 보완 보기 시 501 draw calls / 2,249,888 visible triangles / 501 GPU geometry objects. 장면 node는 held 포함 513개다. 기록의 약 0.43초 전체 demand 완료 및 약 16.7ms frame interval은 **이 로컬 cache/desktop 실행의 관측값**이며 원격망 cold load나 모바일 GPU 보장이 아니다. `renderer.info.memory.geometries`는 개수이며 GPU 메모리 byte 측정이 아니다.
- `browser-ui.json` 및 PNG: 실제 1440·1024·390px, 정면/후면/측면, 키보드 회전/Home, region 변경, 전체 보기, 레이어 토글, 모바일 부위 선택·상세 접기, 3D 우측 경골 클릭→정강뼈/경골/Tibia 카드, 미연결 반대쪽 뼈의 카드 차단, 전경골근 카드와 기시/정지를 확인했다. 최종 학습 창 console error/warning 0건.
- `build.txt`: typecheck 포함 production build 및 기존 content/source/decoder 검증 통과. 기존 계열의 500kB 초과 bundle 경고는 남아 있다. `distribution-gate.json`은 새 held GLB/QA entry가 dist에 포함되지 않음을 확인한다.
- 구현 중 기본 fetch의 receiver 문제를 실제 학습 화면에서 발견해 arrow transport로 수정했고 기본 경로를 다시 확인했다. 작은 화면에서 toolbar와 모형이 겹치는 배치도 수정했다. background 복귀 시 redraw invalidation을 추가했다.

## 남은 일과 후속 경계

T56 필수 단일 장면 통합·지역/레이어 로딩·실패 복구는 통과했다. 이 task의 gaps는 취득/명칭/권리/해부학 검토 및 아래 확장 제한이며, 필수 실패를 합격으로 숨긴 상태가 아니다.

1. 입력에 검증된 superficial/deep 근육 분류가 없다. 현재는 **기록된 지역과 bone/muscle 레이어**, 별도 opt-in 보완 패키지에 따른 demand loading이다. 해부학적 깊이 단계별 자동 분리나 고해상도 LOD 완료를 주장하지 않는다. 필요 시 별도 근거 있는 depth metadata/품질 작업으로 다룬다.
2. 26개 bone-root 누락, 전신 분모, canonical learner mapping, 이름/기시정지 콘텐츠, 사람 검토, 파일별 권리 조정은 미완이다. T57가 보류를 풀거나 원본 이름을 learner 이름으로 사용해서는 안 된다.
3. 기존 초기 지역 route는 유지했다. 브랜드 시작 화면, 전신 홈을 기본으로 여는 흐름, 부위 목록·모형·상세 패널의 최종 배치는 **T57**. 이번 버튼은 장면 기능을 검증하기 위한 최소 learner controls다. T58에서 재질/카메라 여백/확대 품질/성능을 더 다룰 수 있으나 이번에 시작하지 않았다.
4. 선택 강조는 불투명 문맥 색을 옅게 만드는 정책이다. 깊은 구조 노출/투명도 UX는 최종 디자인 과제로 남는다. 구조/기능 텍스트는 기존 데이터를 유지했고 실제 운동 CTA는 계속 준비 중이다.
5. loaded cache는 현재 manifest의 최대 513 node 한도로 유지하며 장면 dispose 시 해제한다. 전신 고해상도 자산이나 신경을 추가할 때는 실제 memory byte 측정과 cache budget/eviction을 별도 설계해야 한다.
