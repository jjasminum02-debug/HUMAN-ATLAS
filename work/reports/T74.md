## 공식 원문과 접근

공식 [다운로드 목록](https://dbarchive.biosciencedbc.jp/en/bodyparts3d/download.html)은 IS-A/PART-OF 트리별 자료를 나누며 PART-OF 99% polygon archive를 별도 항목으로 제공한다. 선택한 [R4 PART-OF mesh 자료 페이지](https://dbarchive.biosciencedbc.jp/en/bodyparts3d/data-8.html)는 `partof_BP3D_4.0_obj_99.zip`과 1,258개 entry를 명시한다. [PART-OF compound-to-ELEMENT relation 페이지](https://dbarchive.biosciencedbc.jp/en/bodyparts3d/data-6.html)는 `partof_element_parts.txt`가 COMPOUND 개념과 이를 구성하는 ELEMENT file ID를 연결한다고 설명한다. 이 relation 표와 로컬 공식 R4 TSV의 exact row를 FMA/BP/FJ 및 각 OBJ 헤더와 대조했다.

공식 [Release 4.0 note](https://dbarchive.biosciencedbc.jp/data/bodyparts3d/LATEST/release_4.0_e.html)는 R4의 날짜와 FJ가 고유 mesh file ID라는 점을 기록하고, 일반 인체 canonical model로 사용 시 자료 오류가 있을 수 있다고 경고한다. 공식 [현재 license 페이지](https://dbarchive.biosciencedbc.jp/en/bodyparts3d/lic.html)는 CC BY 4.0 및 attribution을 표시한다. 그러나 선택된 각 OBJ 헤더에는 이전 CC BY-SA 2.1 Japan 문구가 남아 있다. 두 문구의 파일 단위 적용 관계를 추측하지 않고 redistribution/public release를 계속 hold했다. 상세 URL, DOI, locator 및 접근 범위는 [official-source-checks.json](../evidence/T74/official-source-checks.json)에 둔다.

기존 builder가 mesh page로 잘못 연결하던 IS-A `data-7.html` 참조를 공식 PART-OF polygon mesh page `data-8.html`로 바로잡고, `data-6.html` relation metadata 페이지를 별도 필드로 추가했다. 이 페이지 정정은 FJ/FMA/BP 소속 자체를 변경하지 않았다.

## 산출물과 기술 검증

- 선택 취득 도구: `atlas-data/tools/acquire_bodyparts3d_r4_t74.py`; 공식 PART-OF zip 전체는 받지 않고 frozen member만 HTTP byte-range로 취득했다. [acquisition log](../evidence/T74/source-acquisition.json)는 9/9 success, 29개의 HTTP 206 범위 응답, ETag 일치, CRC/SHA/byte 수 및 전체 archive 미취득을 기록한다. 신규 OBJ 총 payload는 2,675,007 bytes다.
- 새 OBJ 9개와 T74 파생 GLB는 실제 로컬 source-cache에 유지한다. 기존 `.gitignore`는 `atlas-data/source-cache/bodyparts3d-r4/mesh/`와 `converted/`를 unresolved legacy license headers 사유로 제외하므로, 이 파일들은 force-add하지 않고 이번 Git commit에서도 제외한다. exact local hashes/size는 acquisition 및 source manifest에 남기고, 선택 range 재취득 명령은 `python3 atlas-data/tools/acquire_bodyparts3d_r4_t74.py`다.
- 동결 및 재현 변환: `atlas-data/tools/freeze_bodyparts3d_r4_t74.py`, `atlas-data/tools/build_bodyparts3d_r4_t74.py`; 기존 importer와 converter, T50 공통 frame/static pose를 재사용한다. 변환은 `[x,y,z] mm → [x,z,-y] m`이며 x 부호를 보존한다.
- 신규 OBJ 9개마다 archive CRC/SHA/bytes, OBJ 헤더의 exact FJ/FMA/BP/`FMA 3.0 part_of`/영문 표기와 explicit left/right, official PART-OF concept/relation row를 확인했다. 각 표면에 정점·법선·삼각형이 있고 Bounds(mm) 헤더와 정점 extrema의 최대 절대 차이는 0.0001 mm 이하이다. 이는 범위 비교일 뿐 표면 접촉/해부학 정합 증거로 사용하지 않았다.
- 중복 raw hash와 변환 geometry/topology signature는 모두 0개였다. 9개 신규 FJ마다 GLB node 1개이며 GLB position buffer hash가 지정된 변환 결과와 일치한다.
- 신규 GLB: `atlas-data/source-cache/bodyparts3d-r4/converted/t74/T74-bilateral-skull-static-source.glb`, 880,992 bytes, SHA-256 `acf809b37410ed1e56ec2e5630bf080ac92db445a1cb0d76600315baca8c3c88`.

## 실제 브라우저 확인

임시 allowlist localhost QA 페이지에서 T52의 기존 마루뼈, T72의 이마뼈·아래턱뼈·뒤통수뼈, 신규 T74 GLB를 같은 frame/static pose 아래 하나의 `AnatomySceneRoot`와 하나의 Three.js renderer로 실제 로드했다. 신규 target 9개와 재사용 문맥 4개, 총 13 mesh의 front/rear/side 시야를 확인했고 선택 target은 목록/강조가 일치했다. 화면의 canvas는 1000×622 CSS px였으며 console error는 0개였다. 이 QA는 제품 학습 화면이나 해부학 검토가 아니다. 세 각도 캡처를 브라우저에서 확인했으나 이미지 파일은 저장하지 않았다. 브라우저 관찰값은 [browser-verification.json](../evidence/T74/browser-verification.json)에 있다. 종료 시 임시 host의 allowlist 파일 9개만 제거했고 원본 hardlink 내용은 건드리지 않았다.

초기 QA URL 변형 두 개는 허용 context 수 및 신규 target 정렬 assertion에서 의도적으로 거부됐다. preview fixture의 allowlist/order를 실제 T72/T74 manifest와 일치시킨 뒤 `fix2`, `fit1`, `final1`에서 load/render를 통과시켰다. 이 실패는 임시 QA harness 입력 문제였고 production manifest/source bytes를 바꾸지 않았다.
