## 구현

- `atlas-data/schemas/motion-learning.schema.json` 및 `atlas-data/motion/motion-learning.json`을 분리 추가했다. production bundle은 세 collection 모두 빈 배열이다.
- `MuscleAction`은 근육/부분 ID, 출처 claim field·적용 범위·action context, claim value hash와 evidence ref, 자세 조건, 안정화 조건, action별 role과 contraction mode를 담는다. 역할과 수축 양상은 context별로 저장한다. canonical joint ID가 없을 때는 명시적인 `unmapped` 사유로 출처 있는 텍스트만 유지할 수 있지만, 그 action은 MotionDefinition에 연결될 수 없다. 안정화 근거를 기록하지 않을 때도 사유를 요구한다.
- `MotionDefinition`은 side-specific instance, action/joint, 움직이는 bone과 고정 구조, 정적 scene의 revision/hash/frame/unit/pose, 동작 시작·종료 pose 및 pose 근거를 연결한다. 시작 pose는 정적 참조 pose와 같아야 하며 좌우·ID·scene 값은 원자료와 정확히 일치해야 한다.
- `MotionAsset`은 등록 source/license, 파일 URI/revision/SHA-256, `rigged_mesh` 또는 `illustrative_path`, 정적 장면 바인딩, rig node 또는 trajectory, clip pose 범위를 기록한다. `binding_verified`는 validator가 확인한 기술 상태만 뜻하며 사람 승인이나 학습 공개를 뜻하지 않는다.
- `MotionSession`은 앱 실행 중 상태를 위한 TypeScript type이며 저장 schema에는 포함하지 않았다.
- `legacyJointActionAdapter.ts`는 원 JointAction의 정확한 snapshot SHA-256, 원래 reviewState와 evidence IDs를 보존하는 non-persistable preview만 만든다. canonical 실제 row가 0개라 실제 migration preview row는 없다. 기존 T03 JointAction/Review와 `Assessment.targetFunctionIds` 계약은 수정하지 않았다.
- `validate_motion_learning.py`는 T03 JSON Schema validator를 사용하고 canonical/AI claim field 이름, claim value hash, evidence binding, IDs, source, asset SHA/license, side, frame, static/motion pose, rig/trajectory, clip 연결을 검사한다. production validator는 fixture 경로를 읽지 않는다.
- UI를 변경하지 않았고 학습화면에서 task/JSON/검토 상태를 노출하지 않는다. 브라우저 검증은 적용 대상이 아니었다.
