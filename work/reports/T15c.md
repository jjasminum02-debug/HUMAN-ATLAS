## 구현

1. **제품 부위 메뉴** — 기존 순서/ID를 사용해 정확히 12개 product category를 기본 탐색에 표시했다. 하위 근군 탐색 메뉴는 추가하지 않았다. 760px 이하에서는 12개 항목을 가진 native 부위 선택으로 바뀐다.
2. **구조 목록과 출처 범위** — 오직 T15b overlay의 `leg` membership 6개만 종아리 목록에 연결했다. 해당 오른쪽 종아리 파일럿만 BodyParts3D Release 4.0 source/license 안내와 함께 표시한다. 나머지 11개 category는 0개 membership으로 남겨 두고 검색/기존 taxonomy를 근거로 소속을 추론하지 않았다.
3. **타입 선택과 URL** — category/구조 목록을 canonical concept와 연결하고 `region/kind/id/side` URL, muscle part `part` parameter, legacy `?muscle=` adapter, pushState 및 popstate(back/forward)를 구현했다. 명시된 category와 근육 소속이 충돌하면 선택을 비우고 주소를 category-only로 정규화한다. 소속 미확인 전역 검색 결과는 category 없이 남는다.
4. **장면과 빈 자료 상태** — `leg`의 기존 typed pilot selection일 때만 현재 종아리 viewer를 렌더링한다. 장면 없는 머리·목·발 등은 빈 membership·준비 중 설명과 빈 stage를 표시하며 calf scene을 재사용하지 않는다.
5. **반응형과 접근 흐름** — desktop 3열, tablet compact 3열, mobile picker/list → 장면 → 접을 수 있는 설명 카드 순서를 적용했다. category 및 구조 선택은 URL과 상세 카드에 동기화된다. 12부위/구조 메뉴 화면에는 task ID, JSON, 제작 도구를 노출하지 않는다.

## 미완과 경계

- 구조 membership은 여전히 종아리 pilot 6개뿐이다. 나머지 category의 근육/뼈 목록과 실제 장면은 미구현·미할당이며 전신 해부학 coverage를 주장하지 않는다.
- 뼈 정보 카드와 landmark-vs-whole-bone 선택 표시는 T15d 전이므로 추가하지 않았다. 장면 manifest 수명주기, 경쟁 요청 취소, revision cache/GPU 해제는 T15e 전이므로 추가하지 않았다.
- T13 spatial drafts는 `geometry:null` 포함 이전 상태 그대로이며 새로운 부착점/면을 만들지 않았다. 사람 anatomy review 또는 `reviewed` 승격도 없다. T14b는 `needs_human_review` 대기로 남는다.
- 기능/평가/움직임, 자동 배포, Pro mode, 환자 진단·치료·침 시뮬레이션은 수행하지 않았다.
