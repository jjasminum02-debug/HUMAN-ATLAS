## 구현

1. **NavigationCategory와 membership** — 12개 고정 category를 source `region-tree.json`과 분리된 `atlas-data/navigation/atlas-navigation.json`에 추가했다. 현재 실재 입력에 연결한 membership은 T12 right-lower-leg 파일럿 여섯 canonical 개별근을 `leg`에 두는 `decision_only` 행뿐이다. 이유는 `T15b-D01`과 [DECISIONS.md](../DECISIONS.md)에 기록했다. 기존 `regionIds`를 product category로 복사하지 않았다.
2. **Bone identity/mapping** — 깨지지 않는 별도 `StructureInstance` 계약을 선택했다. canonical `Structure(kind=bone)`와 기존 source crosswalk가 모두 확인되는 우측 뼈 9개에 안정 instance ID와 `StructureMeshMapping` 9개를 overlay로 기록했다. `reviewState=needs_review`, `humanReviewState=not_reviewed`; mesh의 표현은 whole-bone context에 한정된다.
3. **미확정 구조 보존** — canonical whole-bone ID가 없는 talus FJ3385 및 제2–4중족골 FJ3353/FJ3355/FJ3357은 매핑이나 Selection을 만들지 않고 미연결 context 네 건으로 보존했다. 새 구조 ID나 좌표를 추정하지 않았다.
4. **SceneManifest/Selection** — T12 오른쪽 종아리 단일 model/frame/unit/pose에 `partial` scene manifest를 기록했다. 근육 mesh 7개와 뼈 mesh 3개는 typed selectable binding이고, 미확정 talus 1개는 null selection context다. 별도 모델인 T13 bone scene을 합치지 않았다. Muscle/whole-bone/landmark는 별개 discriminator로 검증된다.
5. **Migration 및 route adapter** — schema, relational validator, JSON migration builder(`--dry-run`, `--write`, `--check`)와 TypeScript 타입/검증·mesh pick·`?region=...&kind=...&id=...`·legacy `?muscle=...` adapter를 추가했다. 이관은 별도 overlay만 기록하고 canonical/source manifest를 쓰지 않는다. `work/evidence/T15b/migration-dry-run.json`에 입력 hash, before inventory, 변경 요약과 미해결 mesh를 저장했다.
6. **회귀 테스트** — 내폐쇄근 두 category 소속은 test-only synthetic fixture에만 넣었다. 제품 데이터에는 해당 ID가 없다.

task별 설계 결정은 [DECISIONS.md](../DECISIONS.md)의 `T15b-D01`에 있다. 런타임 UI 통합은 T15c 이후이므로 이번에는 학습 화면을 바꾸지 않았다.
