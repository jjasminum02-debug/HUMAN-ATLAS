## 주요 발견: 우선순위 순

### 1. 실제 부착면과 학습 표시 연결이 없다 — 필수

T13은 뼈를 찾는 도구까지 구축했다. 비복근 기시 문장을 클릭하면 대퇴골 전체를 강조한다. 원하신 기시·정지 범위가 색으로 표시되는 상태가 아니다. 경고는 정직하지만 핵심 학습 기능은 미구현이다.

더 중요한 점은 다음 입력 경로다. src/viewer/attachmentContext.ts:16–27은 spatialAnnotationId/geometry를 null, surfaceReviewState를 not_started로만 허용하고 locatedSurfaceAnnotations가 0이 아니면 예외를 던진다. manifest.ts:135 부근도 표면0을 전제한다. 학습 분기 GLBViewer.tsx:195–218에는 실제 annotation overlay가 없고 제작 화면의 AnnotationWorkbench만 로컬 draft를 그린다. 따라서 단순히 /review에서 점·면을 찍는 것으로 학습 화면까지 연결되지 않는다. 기존 context-only manifest는 유지하되 별도 draft spatial layer + importer + learner renderer를 만들어야 한다. 검증을 삭제하거나 draft를 reviewed로 승격해서 우회하면 안 된다.

### 2. 기본 모형이 너무 작아졌다 — 필수

실제 1280×720,1440×900,390×844에서 확인했다. 흰 카드/회색 배경/청록 포인트는 참고와 방향이 맞지만 중앙의 근육은 작은 종아리 조각처럼 보인다. 대퇴골 전체를 포함한 장면 범위가 기본 카메라를 결정한다.

원인: GLBViewer.tsx:109,121의 fitAll(), ThreeViewer.ts:170의 전체 메시 bounds. 사용자 관심 근육을 바꿔도 모든20메시로 카메라가 맞춰진다. 대퇴골을 제거할 필요는 없고 기본 학습 프레이밍을 선택근육+인접 문맥에 맞춰야 한다. 전체 골격 보기는 별도 동작이다. 현재 종아리6개 형상만으로 참고 이미지의 더 넓은 해부학 범위를 충족했다고 해서는 안 된다.

### 3. 우측 카드가 다시 영문 자료 목록으로 길어졌다 — 필수

App.tsx:70–77은 각 attachment claim의 영문 summary를 기본 화면에 버튼으로 전부 출력한다. 비복근에는 기시6개가 요약 아래에 반복돼 1440×900에서도 정지가 첫 화면에서 밀려난다. T10의 간결한 한국어 학습 화면 목표에 대한 회귀다.

한국어 기시/정지 요약을 먼저 함께 보여주고, 위치는 '외측두 · 대퇴골 외측과' 같은 짧은 학습 라벨로 표시해야 한다. 근거별 영문 설명·검토 상태·세부 출처는 펼치기로 옮긴다. 표면 확인 상태는 '설명만 있음/관련 뼈/후보 영역/검토된 영역'으로 구분하되 모든 줄에 장문 경고를 반복하지 않는다.

### 4. 보기 초기화 후 선택 상태가 남는다 — 개선 필요

재현: 비복근 첫 기시 선택→대퇴골 전체 강조→보기 초기화. 전체 장면과 불투명도로 돌아오지만 기시 버튼은 선택 상태이고 '관련 뼈 전체 강조' 안내와 대퇴골 강조색도 남았다. restoreAll()이 부모의 activeAttachmentId를 해제하지 않기 때문이다. 카메라/표시 상태와 React 선택 상태를 같은 초기화 계약으로 묶어야 한다. 이번에는 브라우저 재현만 했고 코드를 고치지 않았다.

### 5. 명칭 검색은 크게 개선됐지만 전체 언어 완료가 아니다

등세모근 검색→승모근 및 부분 후보, 승모근 카드의 僧帽筋, spleinus 검색→두판상근/경판상근 후보를 실제 브라우저에서 확인했다. 38개 도메인 검색 테스트 통과. 승모근처럼 3D 없는 항목에 종아리를 대신 보여주지 않는 것도 정상이다.

비복근의 실제 한자는 여전히 null이며 첫 카드에 표기 대조 중으로 나온다. 총81 overlay 중45개에 한자값이 있다. T11의85/85 checked_with_gaps는 모든 언어 필드 완성과 다르다. 파일럿6개에 필요한 언어 누락부터 닫고, 전신 추가는 동결 catalog 배치로 한다. 판상근 lookup의 canonical 편입도 남았다.

### 6. 생산 앱이 task별 고정 개수/검토상태에 묶여 있다 — 전신 확장 전 정리

manifest.ts의11/9/20, attachmentContext의41/0, needs_review 고정 검사는 현재 스냅샷을 보호하지만 실제 표면 추가·리뷰 전환·전신 배치에서 앱 수정을 강제한다. 스냅샷 숫자는 회귀 fixture로 보존하고, 실행 코드는 manifest의 선언 개수·중복·참조·해시·지원 상태를 검증하도록 바꿔야 한다. 임의 승인이나 해시 검사를 약화하라는 뜻이 아니다.

T12 기존 GLB decoder와 Three GLTFLoader를 브라우저에서 둘 다 읽고 배열을 대조하는 방식은 이전 결과 보존에 유용했다. 전신 데이터에서는 이 동등성 검사를 빌드/검증 단계로 옮길 수 있는지 측정하고, 런타임에는 필요한 integrity 검사를 유지한다. 현재 단계만으로 느리다고 단정하지 않는다.
