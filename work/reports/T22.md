## 결과

기존 정적 GLB decoder를 그대로 두고 Three.js `GLTFLoader.parseAsync()`를 쓰는 별도 `loadAnimationScene` adapter를 추가했다. adapter는 원본 scene hierarchy, `SkinnedMesh` skeleton/skin attributes, animation clips/tracks를 보존하고 source GLB hash, clip, named node bindings, frame과 meter 단위를 검사한다. 축 변환·단위 재조정은 수행하지 않는다. 같은 geometry/material/texture/skeleton/ImageBitmap을 공유하는 객체는 imported bundle dispose 시 한 번만 정리하며 dispose는 멱등이다.

세 표현을 분리했다. 기존 `illustrative_path`를 유지하고, 이동 bone node와 muscle/part 경로 node가 함께 있는 `bone_motion_with_illustrative_path`를 추가했으며, skin/weight를 가진 `rigged_mesh`는 별도 표현으로 유지한다. 결합 표현의 validator는 bone binding과 path binding을 각각 자기 ID 집합에 정확히 맞춘다. production 학습 데이터에는 합성 자산을 넣지 않았다.

첫 후보는 발목 발바닥굽힘 교육용 `bone_motion_with_illustrative_path`로 정했다. 이는 정량적 근육 수축을 묘사하지 않는 기술 선택이며 실제 동작 자산 제작/공개 결정은 아니다. 현재 T21 자료에는 canonical `targetJointIds`가 없고 `MotionDefinition`은 0건이다. 근거가 있는 joint frame/pivot, 이동·고정 구조, pose 범위와 승인 가능한 clip도 없다. 따라서 `motionAssets`는 0건인 채 보류했다.

## 자산·출처 조사

- BodyParts3D Release 4.0의 기존 우측 종아리 파생 GLB는 1 scene, 11 nodes/meshes, skin 0, animation 0, morph target 0이었다. 파일 SHA-256은 `044450c3230bd23869a099d545151cb3d7518da3240a6e59f911f82786edc341`이며 CC BY 4.0 표기를 source manifest에 기록했다. 라이선스와 필수 attribution은 [BodyParts3D 라이선스](https://dbarchive.biosciencedbc.jp/en/bodyparts3d/lic.html)에서 확인했다. 정적 참고 메시로만 둔다.
- `OpenSim_Models`에서 Gait2392 `.osim` 모델 파일은 확인했으며 정확한 파일 안의 모델 크레딧은 CC BY 3.0을 표시한다. 이 표기를 checkout 전체의 라이선스로 확대하지 않았다. 로컬 checkout에는 `.mot/.sto/.trc/.c3d` 샘플과 GLB/glTF/FBX 변환물이 없고, Blender/OpenSim CLI 및 Python 모듈도 사용할 수 없었다. 공식 [Gait2392 설명](https://opensimconfluence.atlassian.net/wiki/spaces/OpenSim/pages/53086215)과 [모델 표](https://opensimconfluence.atlassian.net/wiki/spaces/OpenSim/pages/53090607)를 별도로 기록했다.
- source 후보 파일별 revision/hash/license/attribution과 구조 관찰값은 [motion-asset-sources.json](../../atlas-data/motion/motion-asset-sources.json)에 있다. 둘 다 `motionEligible=false`이며 exact source, reproducible derivation, coordinate, rig, clip, static binding 게이트를 통과하기 전에는 production에 올릴 수 없다.
