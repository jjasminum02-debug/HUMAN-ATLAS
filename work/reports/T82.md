# T82 — 지원 구조 설명·카드 감사와 보완

**결과: 현재 지원 로컬 학습 범위에서 `completed / passed`; 전체 콘텐츠는 `partial`.**

T82는 T81의 지원 근육 카드 전체 데이터 계약을 검사하고, 개발 출처 원장이 learner bundle에 들어가던 경로를 분리했다. 실제 claim이나 canonical binding은 추가하지 않았다. 합격은 현재 지원 범위의 카드 전달과 보안 경계에 한정되며, 전신 해부학의 완성·사람 검토·공개 배포 승인을 뜻하지 않는다.

## 구현

- `learning.ts`가 큰 AI evidence, 구조 claim, legacy 요약, motion 저작 번들을 직접 가져오지 않고 생성된 최소 `learner-card-runtime.json`만 사용하도록 변경했다. generator는 기존 학습 표시 정책을 재사용하며 이름·구조 문장·작용 문장만 투영하고 원문 URL, locator, evidence/hash, review/rights 상태 및 task/저작 식별자를 제외한다.
- 카드 소비자는 action candidate의 표시 가능한 좌우만 사용한다. 구조 문장도 target/source에 대해 이미 고정된 T81 projection만 연결한다.
- runtime 생성 확인과 빌드 후 배포 파일 검사를 build 경로에 추가했다. 검사기는 현재 AI evidence/워크북 disposition의 provenance 표식과 기존 bundle의 노출 기록을 기준으로 learner 배포 JS/HTML/CSS/JSON을 검사한다.
- 변경 전 production App bundle은 1,091,485 bytes였고 `T18-FIELD-*`, evidence hash/access 날짜, StatPearls 및 Hands-on Anatomy 표식이 포함돼 있었다. 새 build는 App bundle 731,451 bytes(gzip 182.01 KB), index bundle 222,370 bytes이며 5개 배포 파일에서 274개 provenance 표식을 검사해 노출 0건을 확인했다. Vite의 500 KB chunk 경고는 남아 있으나 이번 사용자 흐름에서 차단 결함은 관찰되지 않았다.

## 감사 결과와 남은 콘텐츠

자동 원장은 지원 근육 232 source concepts와 462 surfaces, 전체 542 targets / 563 memberships / 12 regions, 기존 canonical HA binding 130개, 역사 분류 163개(6/20/135/2)를 그대로 확인했다. 사적 workbook 257행은 기존 row disposition과 hash만 검사했다. 정확한 영어·부위 후보 40행은 검증 전 후보, 부위 범위 충돌 1행은 충돌, 나머지 216행은 현재 지원근에서 정확 후보가 없는 상태로 유지했다. workbook 원문 내용은 분석하지 않았고 tracked 사본도 만들지 않았다.

구조 claim projection은 기존 7개 target / 양측 14개 source pointer에 한정된다. 기시 claim 6개와 기시 충돌 1개, 정지 claim 7개만 유지했다. 전체 비복근에 속하는 정지를 외측두만의 별도 표면 claim으로 확대하지 않는다. 운동신경 232개와 감각·고유감각 232개는 여전히 미확인이다. 새 claim/canonical binding은 0개다. source-only, 공개 재배포 `held`, `humanReview=not_performed`를 보존했다.

## 실제 브라우저 확인

localhost learner app에서 승모근 상부와 하부의 이름·좌우·선택 표면, 비복근 외측두의 갈래별 기시와 공통 정지 범위, 장비골근의 충돌 유지, 손·발 새끼벌림근의 분리된 이름과 미확인 필드를 확인했다. 승모근 하부는 정면 overview에서 가려졌고 선택만 보기와 맞춤을 적용한 후 뒤쪽 중하부 삼각형 표면을 확인했다. 이는 관찰한 표본 범위이며 근육 전체 형상 승인으로 확대하지 않는다.

브라우저 accessibility snapshot과 화면은 실제 확인했지만, 캡처 파일을 저장하지 못했고 사용 가능한 CUA 탭 API에서 console log를 읽을 수 없어 console은 미확인으로 남겼다. 해당 한계는 정직하게 기록했으며, task의 카드 acceptance는 자동 계약·bundle audit·대표 실제 카드 흐름으로 통과했다.
