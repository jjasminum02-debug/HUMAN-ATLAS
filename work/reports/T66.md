## 실제로 해결한 결함과 계약

1. 기존 손목 입력의 뼈 이름 복구기가 번호가 붙은 손허리뼈·손목뼈를 놓쳤다. 이미 검토된 기시정지의 정확한 field hash/원문에서 명시된 whole-bone 문구만 대조해 source context를 보완했다. 각 side에 실제 extrinsic 근육7표면의 mask/weights를 작성했다. 손목까지 이어지지 않는 척측수근굴근 자갈래 source part는 수동 문맥으로 남겼으며 없는 힘줄을 만들지 않았다.
2. 전체14 후보에 같은 contact-weight 보정을 적용했다. 어깨 가쪽돌림·손목 굽힘·엉덩관절 벌림의 좌우6패키지는 원본 overlap을 보존하고 새 sampled containment0, flips0, area ratio≥0.1을 충족했다. 원래 range·기하 기준·96MiB 활성 형상/1M triangles/20MiB overview 예산을 유지했다.
3. 어깨 가쪽돌림의 좌우 회전 부호가 반대였던 후보를 수정했다. 고정 X-left/Y-up/Z-anterior frame에서 앞쪽 probe가 몸 중심에서 멀어지는 방향으로 오른쪽−8도/왼쪽+8도를 결속했다. 정성적 방향은 [OpenStax 9.5](https://openstax.org/books/anatomy-and-physiology-2e/pages/9-5-types-of-body-movements)에 대조했으며 이 자료가 실측 축·mask·ROM을 제공한다고 쓰지 않았다.
4. 실제 브라우저에서 왼쪽 뼈가 작은 덩어리처럼 잘못 보이는 GLB export 결함을 발견했다. Quaternion만으로 reflection을 표현할 수 없으므로 음의 determinant를 X scale에 보존하고 proper rotation을 작성했다. 원본 mesh/matrix는 바꾸지 않았다. r13의 실제 quaternion/translation/signed scale/morph buffer를 **모든9 authored key, 모든 member**에서 원본 frame trajectory와 대조했다. 최대 world 오차는약1.875e−7m이며≤1e−6m 기준을 충족했다. Three.js 실제 로더/mixer를 통과한 rigid member의 모든 정점·키 검사도 통과했다. 이전 r7의 왼쪽 배치 화면은 합격 근거에서 제외했다.
5. HA canonical joint ID가 없는 source-local 자료의 재생을 막던 계약에 별도의 `source_family_bound`를 구현했다. Source/측/family/frame/pose/field locator hash/실제 GLB/기하·접촉 QC를 결속하고 canonical joint 계약은 유지했다. 빈 canonical ID를 승인한 것이 아니며 새 HA 연결은0이다. unrelated family·wrong side·wrong field·같은 buffer의90도 승격 등을 거절하는 음성 사례를 검사했다.
6. Source member 행/배열·rig·pose·고정 binding을 정확하게 공유하는 runtime projection을 만들었다. 반복 복제 상태에서 관측한6,513,174 bytes가 현재**1,591,310 bytes**로 줄었다(약75.6%). 모든 selector·source hash·자산·각도를 보존했고 LOD나 형상을 줄이지 않았다.
