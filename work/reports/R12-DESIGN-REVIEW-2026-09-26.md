# T14b 이후 코드 검토와 R12 설계 개정

날짜: 2026-09-26. 범위: 현재 체크아웃의 코드·데이터·작업 기록 검토, 설계와 후속 task 수정. **앱 기능 구현 task는 실행하지 않았다.**

## 판단

현재 코드는 종아리 파일럿으로서 재사용할 기반이 있다. 학습 화면과 제작 화면 분리, 이름 검색, Three.js 선택·카메라, 부착 초안의 출처·좌표·해시 검증은 유지할 가치가 있다. 그러나 전신 Atlas나 정확한 기시·정지 표면이 완성된 상태는 아니다. 단순히 기존 T15 이후 자료 입력을 진행하면 새 12부위 탐색과 뼈 클릭 요구를 충족하지 못하므로 T15a–g를 먼저 수행하도록 변경했다.

T14b는 검토 자료 묶음을 작성한 상태다. 실제 사람의 의견과 승인 기록은 0이며 needs_human_review를 유지한다. 이 대기는 해부학적 승인 상태의 승격을 막지만, 명칭·탐색·장면 로딩 같은 독립 개발을 막지는 않는다.

코드 확인 위치: `atlas-web/src/data/learning.ts`의 label/korean/english/hanja projection과 검색 alias, `src/ui/App.tsx`의 근육 중심 선택 및 이름 카드, `src/viewer/GLBViewer.tsx`의 chooseMesh와 고정 장면 로딩, `atlas-data/catalog/region-tree.json`의 원자료 분류. chooseMesh는 individual_muscle 또는 muscle_part에 대해서만 정보 카드의 선택을 갱신한다. 따라서 뼈 메시를 보여주는 기능과 뼈를 학습 가능한 구조로 선택하는 기능은 구분해야 한다.

이번에는 실제 브라우저를 새로 열어 미감을 판정하지 않았다. UI 판단은 현재 코드와 T14a의 기존 브라우저 검증 기록에 근거한다. 참고 이미지와 동일한 외형을 달성했다고 주장하지 않는다. 전신 모델의 외형은 화면 코드만으로 해결되지 않으며, 부위별 실제 근육·뼈 자산의 품질·좌표 정합·라이선스가 필요하다.

## 확정한 제품 방향

- 사용자가 지정한 12개 부위만 기본 탐색으로 사용한다. 표정근·씹기근·외안근 등 하위 메뉴는 만들지 않지만 해부학 개념 자체는 보존한다.
- 동일 근육은 여러 부위에 소속될 수 있다. 사용자 표의 내폐쇄근처럼 두 부위에서 같은 ID를 사용한다. 구조의 소속과 주변 문맥으로 보이는 뼈의 장면 포함은 별개다.
- 기본 표시명은 삼각근, 보조 이름은 어깨세모근·deltoid다. 실제 한자 문자는 요구하지 않는다. 이미 수집한 원문 근거는 보존하며 추가 한자 조사와 제품의 한자 누락 경고는 폐기한다.
- 큰 3D 화면과 선택한 구조의 짧은 정보 카드가 중심이다. 상세 근거는 펼쳐 본다. 근육과 뼈는 서로 다른 정보 카드를 사용한다.
- 부위별 장면을 지연 로드한다. 빠른 부위 전환, 뒤로가기, 공유 자산, 선택 상태, 좌표계와 공간 초안의 유효성을 함께 관리한다.
- 경혈·MPS·통증사냥법·Pro mode는 이후 별도 설계이며 이번에 구현하거나 미리 숨겨 넣지 않는다.

## 변경한 문서와 실제 산출물

`design/2026-09-25-muscle-atlas/06-REGION12-MUSCLE-BONE-REVISION.md`가 현행 개정의 기준이다. `region12-navigation.design.json`은 12개 분류의 설계 데이터이며 런타임에 연결하지 않았다. 00–04, AGENTS.md, STATUS.md, DECISIONS.md, T15–24 명세에 우선 규칙과 후속 흐름을 반영하고 T15a–g 상세 명세를 추가했다. 기존 task 보고서는 수정하지 않았다.

원자료의 18개 분류를 삭제하거나 실제 anatomical membership을 추정하여 추가하지 않았다. UI에서 실제 한자가 사라지는 것은 T15a 구현 이후이며, 이번 문서 개정을 이미 구현된 것으로 세면 안 된다.
