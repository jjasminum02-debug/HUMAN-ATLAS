## 원문 identity, 부위와 좌우

각 source는 BodyParts3D Release 4.0 `IS-A` archive에서 취득했다. `File ID`, `Representation ID (BP)`, `Concept ID (FMA)`, English name, build-up logic, raw license header, `Bounds(mm)`를 OBJ 원문과 대조했고, 공식 R4 concept/ELEMENT/parent rows 및 archive member CRC32도 검증했다. OBJ bytes는 SHA-256과 함께 raw source cache에만 보존했다. 좌우는 공식 side-specific FMA/name 행에서 결정했다. FJ 이름 접미사만으로 좌우를 추정하지 않았다. x 부호는 T50/T69 frame의 일관성 검사로만 사용했고 side 판정의 근거로 사용하지 않았다.

## 좌표, bounds, mesh와 parent 중복

각 파일의 unit은 원문 `Bounds(mm)` header로부터 mm로 기록했다. 파생 변환은 T50/T69의 `[x,y,z] mm → [x,z,-y] HUMAN_ATLAS_RH_M_XLEFT_YHEAD_ZANTERIOR m`이며 x 부호 보존, mirror/recenter 없음, pose `bodyparts3d-r4-static-reference`다. OBJ bounds header와 vertex extrema는 별도로 저장했다. 최대 차이는 FJ1395에서 0.0837 mm이며, 파생 GLB bounds는 원문 header 상자가 아닌 실제 vertex extrema에서 계산했다. bounds는 surface 접촉이나 부착 근거로 취급하지 않는다.

같은 FJ를 가리키는 generic part 및 side-specific 의미행은 하나의 source node로 합쳤다. T77/T79 active parent와 exact FJ 집합을 비교해 T101 ID 충돌과 중복 node가 없음을 확인했다. official R4 IS-A table에서 검색한 정확한 네 muscle name (`flexor hallucis brevis`, `gastrocnemius`, `biceps femoris`, `adductor hallucis`)과 일치하는 whole-muscle aggregate concept/member는 없었다. 비복근의 두 기존 우측 머리 FJ1394/FJ1397는 parent 장면의 같은 generic head part를 나타내고, T101의 FJ1394M/FJ1397M는 그 왼쪽 대응 source member다. 원문 source name과 x 범위가 반대쪽을 가리켜 둘을 whole-muscle parent로 합치거나 하나를 제거하지 않았다. 정확한 family-member rows, runtime intersection, 처리 정책은 T101 source manifest와 validation evidence에 남겼다.

## 파생 GLB와 learner scene

- 파생 chunk: `t101-lower-limb-muscle.glb`; 10개 source FJ → 고유 node 10개, 629,336 bytes, SHA-256 `bffce0beacad6feede926b5de0e81c773cfc51ae1aca45e367c3868b638ab859`.
- 새 sibling `source-manifest.json`과 `integration-extension.json`을 추가했다. 이 extension은 T77 manifest, T95 product overlay, T79 source manifest 및 T79 extension의 hash를 묶고 같은 `AnatomySceneRoot`/renderer/camera contract에 append한다. 새 renderer/viewer는 없다.
- T101 assets는 각각 source-only/unbound, stable canonical IDs 없음, learner label 없음, `humanReviewed=false`, 공개 재배포 held다. 항목별 기술 검사 뒤 이 exact subset의 **로컬 정적 표시만** 허용했다. 이 로컬 허용은 source 권리 승인이나 사람 해부학 검토를 뜻하지 않는다.
- raw OBJ 및 derived GLB는 기존 ignore source-cache 아래에 두어 커밋하지 않는다. 변환 및 manifest는 선택 원문이 캐시에 있을 때 재현 가능하다. 원문 archive 전체는 취득하지 않았다.

## 실제 브라우저 및 검증

1280×720 로컬 브라우저에서 기존 learner app을 열고 전신·종아리·발·넙다리 보기를 전환했다. 한 WebGL canvas를 유지했고 console error/warning은 0이었다. 발 보기에는 양측 발바닥 근육 표면이 보였으며 UI는 계속 `0개 연결된 근육`을 표시했다. 이는 source-only mesh가 표시되지만 canonical learning name/selection이 생기지 않았다는 기대 상태다. 종아리 화면에는 양쪽 근육과 발이 함께 보였고, 넙다리 화면에는 양쪽 뒤넙다리 부위가 보였다. 발에서 근육 layer를 끄면 근육 표면이 사라지고 뼈만 남았으며 다시 켜면 표면이 복귀했다. 전신 보기로 돌아갔을 때 모형은 동일한 중앙 장면과 단일 canvas에 남았다. 실제 화면 캡처는 검토했으나 이미지 파일로 export하지 않았다.

로컬 Vite server의 runtime manifest 응답은 HTTP 200이고 T101 chunk는 동결 ID 10개만 담았다. 별도 loopback 요청으로 받은 GLB는 629,336 bytes이고 SHA-256이 runtime manifest와 같았다. Browser/manifest 세부 기록은 `work/evidence/T101/browser-validation.json`이다.
