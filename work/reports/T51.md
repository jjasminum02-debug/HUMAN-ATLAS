## 실제 원본과 권리 기록

공식 BodyParts3D Release 4.0 README/릴리스 기록, 다운로드 목록, 라이선스 페이지와 6개 공식 raw TSV를 확인했다. 현재 공식 라이선스 페이지는 CC BY 4.0과 귀속 문구를 안내하지만, 기존 local OBJ 파일의 원문 header에는 CC BY-SA 2.1 Japan이 기록돼 있다. 두 관찰을 함께 보존하고 파일 단위 권리 정합이 확인될 때까지 OBJ 및 파생 GLB의 재배포 상태는 hold다. [공식 README](https://dbarchive.biosciencedbc.jp/data/bodyparts3d/LATEST/README_e.html), [공식 다운로드 목록](https://dbarchive.biosciencedbc.jp/en/bodyparts3d/download.html), [공식 라이선스](https://dbarchive.biosciencedbc.jp/en/bodyparts3d/lic.html)

metadata raw 파일은 HTTPS로 2026-09-27에 받아 `atlas-data/source-cache/bodyparts3d-r4/metadata/`에 고정했다. 정확한 URL, bytes, row count, SHA-256은 source manifest의 `source.metadataFiles`에 기록되어 있다. 6개 파일에는 FMA concept/BP representation, IS-A/PART-OF 포함 관계, compound context에서 FJ ELEMENT mesh로 이어지는 인덱스가 포함된다.

공식 인덱스는 IS-A 2,234 FJ, PART-OF 1,258 FJ를 가리킨다. 두 tree에서 함께 참조되는 1,258 FJ는 geometry 한 개로 deduplicate하고 source context 목록은 모두 유지한다. 총 3,432개 unique FMA concept, IS-A/PART-OF concept 및 element 행을 별도 기록한다. FMA, BP, FJ, HUMAN ATLAS 안정 ID는 별도 namespace이며 기존 명시적 crosswalk가 있을 때만 HA ID를 붙인다. 이름만으로 새로운 stable ID를 만들지 않는다.

T50/T15g에 이미 있던 20 OBJ 각각을 `source-cache/mesh/IS-A/`로 byte-identical 복사하고 20개 SHA-256·헤더 identity·원경로·용량을 `work/evidence/T51/source-cache-file-inventory.json`에 기록했다. 해당 20개는 모두 우측 표본이다. 이번 실행에서 공식 136 MB IS-A 및 62 MB PART-OF 압축 mesh archive는 다운로드를 시도하지 않았다. 따라서 로컬에 없는 2,214 FJ는 `not acquired / not attempted`이며 download failure 0건이다. `.gitignore`에는 권리 정합이 미해결인 로컬 OBJ·GLB·cache index·추후 archive만 제외하도록 추가했다. 공개 metadata TSV와 귀속 README는 manifest 재생성을 위해 추적한다.

## 변환과 ID 계약

- 재현 명령: `python3 atlas-data/tools/ingest_bodyparts3d_r4.py --all`
- 외부에서 별도로 확보한 OBJ의 명시적 입력: `python3 atlas-data/tools/ingest_bodyparts3d_r4.py --ingest-obj /path/to/FJ....obj`. 이 작업은 네트워크 요청을 하지 않는다. 공식 Release 4.0 인덱스의 FJ와 OBJ header의 FMA/BP/build-up identity가 맞지 않으면 거부하고 geometry 없는 임시 ID를 만들지 않는다.
- 추가로 들어온 캐시 OBJ는 `--build` 시 size/hash/header를 재검증한다. 특정 cache file ID 변환은 `--convert-file-id FJ... --convert-output /path/to/output.glb`; 이 출력은 학습 부위 membership이나 제품 준비를 만들지 않는다.
- 기존 T50 검증 frame 계약을 적용: source mm → HUMAN ATLAS RH meters `[x,y,z] -> [x,z,-y]`. 우측/좌측은 source identity에서 가져오며 반대편 mesh를 복제/반사하지 않는다. source 단위는 기존 T50/local sample 근거로만 기술하고, 공식 raw table 전체의 단위 선언은 확인되지 않아 미확인으로 남긴다.
- static source reference pose만 주장한다. 정형 관절 pose, rig/skin/morph, 움직임, 표준화된 해부학 자세를 추가하지 않았다. 공식 페이지가 안내하는 단일 99%-reduced bundle 표기를 기록하지만 local OBJ의 정확한 reduction profile과 multi-LOD chain은 검증되지 않았다. 새 LOD를 만들지 않는다.
- T51 내부 QA 변환 GLB: 20 mesh, 961,888 bytes, SHA-256 `81e1f72a2a630ae2e259ccdd2a020fb86f08c551cfaa076fbde36353a434f382`. 원본 20 OBJ의 해시, mesh/geometry/topology/normal hash와 frame/identity overlay는 `work/evidence/T51/converted-sample.json`에 있다. cache 복사본 및 GLB는 로컬에 보존하지만 권리 미해결로 Git에는 넣지 않는다. 새 checkout은 추적 중인 원본 sample에서 `--all`로 재생성할 수 있다.

## T15g drift

역사 T15g artifact의 denominator는 `false/null/null`을 유지한다. T51 새 manifest는 historical 10개 bone ID 목록과 현 canonical catalog 11개 목록을 별도 기록한다. 추가된 현재 ID는 `HA-S-TALUS` 하나이며 역사 목록에서 빠진 현재 ID는 없다. 원본 T15g inventory를 재작성하지 않았다.

기존 `atlas-data/catalog/test_t15g_inventory.py`를 별도로 실행했으나, T51 시작 시점부터 추적 중이던 T15g builder의 고정 assertion `len(bone_structures) == 10`이 현재 canonical catalog의 실제 11개 bone 구조 때문에 실패했다. 이 입력들은 시작 baseline과 같고 T51은 기존 T15g 파일을 변경하지 않았다. 새 T51 inventory는 10→11 drift를 별도로 출력한다. 이번 task에서 역사 builder/test를 바꾸거나 오래된 T15g artifact를 다시 만들지 않았다. 이 기존 validator failure를 받아들일 수 있도록 T15g 재현 검사를 역사 snapshot 기준으로 조정하는 일은 별도 유지보수 gap으로 남긴다.

## 미완 및 경계

1. 전체 공식 mesh archive를 받지 않았다. 2,214 FJ의 예상 목록만 있으며 아직 미수집/미시도다.
2. 공식 raw index에 source-wide unit field가 없고, sample 파일 header에는 이전 license가 있어 전체 파일 권리/단위 확인은 미완이다. file-level rights reconciliation 전 재배포하지 않는다.
3. region source root는 이름 기반 product navigation이나 사람 검토 membership이 아니다. 신규 소속, 반대편 자산, canonical 전신 분모, full-body scene, quality/LOD validation, skeletal rig와 continuous motion은 이 범위에서 구현하지 않았다.
4. T15g historical validator의 10-vs-11 failure는 고치지 않고 명시적으로 남겼다.
