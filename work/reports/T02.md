- 일자: 2026-09-25

## 결과 요약

공식 LSDB Archive의 BodyParts3D Release 4.0에서 우측 종아리 pilot 6개 개념을 찾았다. Gastrocnemius는 오른쪽 medial/lateral head가 별도 개념과 파일로 제공되어, 6개 pilot 개념은 **근육 mesh 후보 7개**로 표현된다. 함께 볼 우측 tibia, fibula, talus, calcaneus **뼈 mesh 4개**를 합해 총 **11개 OBJ**를 가져와 원본 내용 그대로 보관했다. 상위 ZIP 전체는 저장하지 않았다.

요청된 T02 통과 조건 중 source ID가 연결된 실 mesh, 한 근육과 관련 뼈의 우측/방향 일관성, 여섯 pilot의 mesh 지원 상태를 충족한다. `TECHNICAL_GATE`의 범위만 통과했으며 해부학 및 assessment gate는 미검토로 유지한다.

## 출처, 이용 조건 및 취득 범위

- Dataset: BodyParts3D Release 4.0, IS-A tree, `isa_BP3D_4.0_obj_99.zip`. Release data 날짜는 2013-06-19이며, archive license 페이지 갱신일은 2025-02-27로 서로 다른 날짜다.
- 공식 archive가 제공한 ZIP 크기: 142,903,898 bytes. HTTP Range 지원을 확인하고 필요한 ZIP directory/member 구간만 요청했다. 재시도를 포함한 전송량은 2,656,859 bytes(24 MiB task budget 아래)였고 archive ZIP은 로컬에 저장하지 않았다.
- 소스 archive member의 CRC는 멤버 추출 시 검증됐다. 11개 OBJ의 총 로컬 크기는 2,256,442 bytes이며, 각 SHA-256·CRC32·member 경로·크기는 `work/evidence/T02/source-transfer.json`과 `work/evidence/T02/geometry-inspection.json`에 기록했다.
- archive README는 성인 남성 reference model 및 atomic element OBJ를 통한 compound 표현을 설명한다. Release note는 canonical model의 오류/결측 가능성을 경고한다. 따라서 이 자료는 형태 후보이며 모든 인체/변이의 정답이나 부착 증거가 아니다.
- archive download page: [BodyParts3D download listing](https://dbarchive.biosciencedbc.jp/en/bodyparts3d/download.html)
- current archive terms: [LSDB Archive license page](https://dbarchive.biosciencedbc.jp/en/bodyparts3d/lic.html). 페이지와 [BodyParts3D README](https://dbarchive.biosciencedbc.jp/data/bodyparts3d/LATEST/README_e.html)는 CC BY 4.0 및 다음 귀속 문구를 안내한다: `BodyParts3D, © The Database Center for Life Science licensed under CC Attribution 4.0 International`.
- 권리 기록 한계: 선택한 구형 OBJ 파일 comment에는 이전 CC BY-SA 2.1 Japan 안내가 포함되어 있다. comment는 보존했고 편집하지 않았다. manifest에는 두 사실과 현재 archive의 조건/귀속 판단을 함께 기록했다. 이번 task에서 외부 공개·재배포는 하지 않았다. 배포 전 조건을 재확인한다.

## 좌표, 단위와 포즈 결정

공식 [coordinate-system diagram](https://dbarchive.biosciencedbc.jp/archive/bodyparts3d/images/coordinate_system.png)은 단위를 mm로 하고, +X를 환자 왼쪽(따라서 X<0은 오른쪽), +Y를 후방, -Y를 전방, +Z를 상방으로 정의한다. Atlas 내부 좌표는 오른손계 m, +X 환자 왼쪽, +Y 머리/상방, +Z 전방으로 정했다.

```text
[x_atlas, y_atlas, z_atlas] m = [x_source, z_source, -y_source] mm / 1000
```

행렬 determinant는 +1이며 반사는 없다. 모든 11개 파일의 실제 정점에서 source X 최대값이 0보다 작음을 확인해 오른쪽 부호 보존을 검사했다. Source 자료는 adult male의 고정된 reference geometry다. 공식 좌표 그림은 축의 의미를 정의하지만 관절별 표준 pose를 말하지 않으므로 `bodyparts3d-r4-static-reference`로 기록했고, 이를 표준 해부 자세라고 부르지 않는다.

## Viewer trial

임시 로컬 페이지 `work/evidence/T02/calf-viewer-trial.html`에서 OBJ 정점을 브라우저 canvas에 표시했다. 이는 앱 구현물이 아니다.

- 기준 환경: macOS desktop, Codex In-app Browser, viewport 810 × 752 CSS px, DPR 2. 실제 컴퓨터 모델은 확인하지 않았다.
- 11/11 OBJ가 로드됐다. 총 21,480 vertices, 30,032 polygon faces. Runtime/asset error counter는 0이었다.
- 11개 원본 OBJ의 각 `f` 행이 삼각형임을 별도로 확인했다. 따라서 viewer의 fan triangulation 결과 face 수 30,032는 원본 face 행 수와 일치한다.
- 전체 레이어 선택, 드래그 회전, 휠 확대/축소, 정면 보기 전환을 실제 브라우저에서 조작했다.
- 마지막 캡처 장면: right soleus FJ1437 + right tibia FJ3387, fibula FJ3366, talus FJ3385, calcaneus FJ3360. 정면에서 메시들이 midline X=0의 환자 오른쪽에 놓이고 상방 축이 위로 향하는 것을 확인했다. 이 공통 source coordinate로 본 상대 배치/표시 시험이지 attachment 또는 identity의 사람 검토가 아니다.
- `work/evidence/T02/calf-viewer-trial.png`: PNG signature/청크 CRC를 검사한 1544 × 902 screenshot, 177,200 bytes.
- 최종 캡처 후 접근 가능한 CUA `tab.dev.logs({})`는 빈 entry 목록을 반환했다. 그 capture window의 콘솔 결과와 화면상 `runtime/load errors 0`를 기록했다. 로그 API가 이전 navigation까지 복구한 것은 아니다. 상세 브라우저 조작은 `work/evidence/T02/viewer-trial.log`, 콘솔 캡처 결과는 `work/evidence/T02/browser-console.json`에 있다.

## 검증 결과 및 한계

`python3 work/evidence/T02/validate_t02.py`가 manifest/crosswalk와 실 OBJ hash·정점·면·경계, 변환·좌우, license/comment 기록, screenshot CRC, browser evidence, 사용자 원본·OpenSim 보존을 검사했다. 명명된 모든 자동 검증 항목이 통과했고 결과는 `work/evidence/T02/validation.json`에 있다. Staged `git diff --check`는 작성한 문서·코드·manifest에 대해 확인한다. 원본 OBJ는 source bytes를 그대로 보존해 trailing whitespace도 수정하지 않으므로 해당 raw asset 경로를 이 whitespace 확인에서 제외하고, 원본 hash 일치로 무변경을 검증한다. 기존 root README, AGENTS, design/템플릿 10개 파일의 task 시작 전·후 SHA-256이 일치한다.

통과는 기술적 파일·ID·좌표·화면 표시 범위에 한정된다. 전신 자산, 실제 근육 identity 검토, 부착 영역·좌표, 관절 pose, 해부학 설명 또는 임상 내용은 만들거나 승인하지 않았다. BodyParts3D는 99%-reduction candidate이며 release note에 오류 가능성이 적혀 있다.
