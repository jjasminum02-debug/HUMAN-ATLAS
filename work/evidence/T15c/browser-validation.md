# T15c 실제 브라우저 검증

날짜: 2026-09-26  |  경로: learner `/`  |  서버: `http://127.0.0.1:5173/`

검증은 Codex In-app Browser의 실제 페이지에서 수행했다. `/review`에 들어가지 않았고 브라우저 저장소를 읽거나 변경하지 않았다.

## 뷰포트와 화면

- **1440×900**: viewport override 적용. 기본 탐색에는 고정된 제품 부위 12개가 보이고, 종아리는 여섯 pilot 근육만 목록에 나타났다. 가운데에 종아리 장면, 선택 근육 설명 카드가 연결됐다.
- **1024×768**: 세 열 화면을 육안 확인했다. 왼쪽 12부위/구조목록, 가운데 종아리 장면, 오른쪽 선택 근육 이름·기시·정지 요약이 한 화면에 나타났다.
- **390×844**: 단일 native 부위 선택과 12개 선택지가 나타났다. 종아리의 여섯 항목과 출처 고지가 두 열 목록으로 표시됐고, 그 아래 장면 및 접을 수 있는 근육 카드가 보였다. 콘텐츠가 화면 폭 밖으로 나가는 현상은 캡처에서 보이지 않았다.
- 세 크기에서 사용자 화면에 작업 ID, JSON, 제작 도구 이름은 나타나지 않았다. 학습 카드의 출처/자료 상태는 기존 learner 콘텐츠다.

## 선택·URL·히스토리

- 종아리 typed deep link `?region=leg&kind=muscle&id=HA-M-000002&side=right`에서 가자미근 카드와 선택 상태를 확인했다.
- 예전 `?muscle=HA-M-000001` 링크는 우측 비복근을 선택하고 typed `region/kind/id/side` URL로 정규화됐다.
- 키보드로 머리 항목에 포커스한 뒤 `Tab`, `Return`을 눌러 목으로 이동했다. URL과 선택된 부위가 함께 바뀌었다.
- 브라우저 뒤로/앞으로로 목 ↔ 머리 상태와 URL이 함께 복구됐다.
- 390px에서 native picker로 머리/종아리/발을 전환했고, 종아리 목록에서 후경골근을 선택했을 때 `HA-M-000004` URL과 카드가 일치했다.

## 미지원 부위와 미할당 구조

- 머리·목·발은 구조 연결 0개와 준비 중 안내를 표시했다. 이 상태에서는 3D viewer를 만들지 않으며 종아리 모델도 표시되지 않았다.
- `?region=foot&kind=muscle&id=HA-M-000001&side=right`는 `?region=foot`으로 정규화하고 선택 불일치 안내를 보였다. 종아리 근육을 발 장면으로 잘못 표시하지 않았다.
- 종아리 `side=left` typed deep link는 선택 근육 카드는 보존하지만 오른쪽 전용 장면을 숨기고 왼쪽 종아리 장면 준비 중으로 안내했다.
- 전역 검색의 미할당 삼각근 선택은 부위 ID 없이 `?kind=muscle&id=HA-M-000030`에 남았다. 검색 결과는 “부위 연결 준비 중”으로, stage는 확인된 장면 없음으로 표시했다.
- 종아리 목록의 멤버는 T15b overlay의 기존 여섯 근육이며, 기존 BodyParts3D Release 4.0 source/license 안내를 유지했다. 다른 category membership은 추가하지 않았다.

## 브라우저 런타임

- 콘솔 error/warn: 0 (`tab.dev.logs`, levels error/warn).
- 캡처 화면을 상호작용 중 육안 확인했다. 화면 이미지를 저장 파일로 복제하지는 않았다.
