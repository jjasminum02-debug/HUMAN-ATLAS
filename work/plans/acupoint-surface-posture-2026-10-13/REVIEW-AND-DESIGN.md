# 전신 피부 → 361혈 표시 → 영역·내용 → 마지막 취혈자세

2026-10-13 r2. 사용자의 최신 정정이 이전 `locating-posture → 점 확장` 순서를 대체한다. 진행 중인 Luna `portfolio-content`는 그대로 끝낸다. 이 문서는 설계이며 구현 완료/기존 partial의 승격이 아니다. 현재 실행 프롬프트는 [PROMPTS-IN-ORDER.md](PROMPTS-IN-ORDER.md) 하나다.

## 최종 제품의 모습

기존 전신 인체 한 개를 그대로 사용한다. 뼈·근육·신경 옆에 **피부** 버튼이 있고, 피부를 켜면 얼굴·귀·손가락·발가락을 포함한 자연스러운 전신 외피가 같은 해부학 모형을 덮는다. 경맥을 고르면 그 피부에 점과 경로가 붙고, 경혈을 고르면 이름·한국어 위치·취혈 방법을 읽는다. 경맥 영역은 같은 피부 위의 색 면으로 나타난다. 피부를 끄면 기존 해부 관찰로 이어진다. 별도 인체 창·canvas·카메라는 만들지 않는다.

**먼저 정지 모델에서 361혈 전체를 갖춘다. 그 뒤에 자세가 필요한 혈을 전수 조사하고 구현한다.** 자세를 구현하지 않았다는 이유로 정지 모델의 위치 등록을 대기시키지 않는다. 그렇다고 자세에 따라 달라지는 함요를 현재 모델에 이미 구현한 것으로 부르지는 않는다. 현재 기준 자세에서의 교육용 위치와 최종 취혈 자세 지원은 별도 필드다.

## 이번에 실제 비교한 피부 소스와 결정

**MakeHuman 공식 core base mesh를 피부 제작의 주 입력으로 선택한다.** 원본 파일을 확보했고 `body` 그룹 13,380 vertices / 13,378 quads / 26,756 triangles를 확인했다. helper와 관절 큐브까지 합친 OBJ 전체를 피부로 내보내지 않는다. [소스 비교·hash](skin-source-review/selection.json), [형태 미리보기](skin-source-review/makehuman-shape-preview.png).

| Zygote의 인체 피부 | 전신 외피를 별도 anatomy layer로 제공하는 상용 제품 | 외관/레이어 품질 참고. 공개 무료 자산으로 오인하지 않음 |

MakeHuman 선택은 **구현 입력 선정**이지 ZA 정합 완료 판정이 아니다. 현재 시각 미리보기는 source shape 확인이며 제품용 smoothing/material, 완전한 성인 체형 설정, ZA 관통 검증 전이다. 단일 macro target의 시험 결과를 완성된 MakeHuman 캐릭터로 오인하지 않는다. 실제 생산 레시피는 기존 ZA 체형과 자세에 맞춰 확정한다.

공식 source asset 권리가 확인된 피부까지 이유 없이 `rights=held`로 만드는 것은 불필요하다. 피부 자체의 확인된 권리와 기존 ZA/BP3D의 개별 권리를 분리한다. 이번 선택으로 기존 모델의 재배포 상태를 승격하지 않는다.

## 피부 구현은 두 산출물로 분리

### AT10 / skin-fit — Sol xhigh

확보한 MakeHuman base/target/license를 재사용하여 **전신 정합 피부 파일**을 만든다. 실제 파일이 있는데 이름 검색부터 반복하지 않는다. 기존 ZA geometry는 고정하고 피부의 체형·팔 벌림·손 방향·발 위치를 맞춘다. 정합은 골격 기준점 → 부위별 형태 조정 → 관통/과도한 간격 검사 순서다. 전신 uniform scale 또는 근육으로 무조건 shrinkwrap하는 것만으로 끝내지 않는다.

- MakeHuman 내부 단위 dm → m 0.1은 공식 설명에 근거한다. MPFB에서 이미 m로 export했다면 중복 적용 금지. source 축/좌우는 실제 joint 그룹과 실물로 확인하고 변환을 한 번만 적용한다.
- 원본 vertex/face ID와 derived topology mapping, UV, normals, source/derived hash, 재실행 recipe를 남긴다. helper/의복 면은 외피에서 제외하되 내부 joint 표지는 정합 작업 입력으로 보존한다.
- 얼굴·귀·쇄골/어깨·겨드랑·팔꿈치·손목/손바닥/손가락·흉복부·등/천골·샅·무릎·발목/발바닥/발가락을 모두 점검한다. 부위별 관통/간격 수치와 시각 결과를 기록한다. 모든 부위에 같은 피하 두께를 강제하지 않는다.
- 피부가 없는 구강/잇몸 같은 점막 구조는 외부 피부로 대체하지 않는다. 기존 anatomy 또는 작은 별도 교육용 점막 면에 연결할 계약을 만든다. 이를 핑계로 전신 외피 전체를 미완 대기시키지 않는다.
- 배꼽·유두·주름 등 관찰 지표와 해부 landmark registry를 함께 제공한다. 일부 지표는 출처 기반 교육용 authoring이 필요하다. 모든 경혈 위치가 원본 피부에 정답으로 새겨져 있을 것이라 가정하지 않는다.
- 완성물: 전신 피부 GLB, 정합/지표 manifest, 제작 recipe, 전후면·양측·얼굴·손발 근접 검사. **점 361개와 취혈자세를 이 단위에 섞지 않는다.**

### AT10 / skin-runtime — Sol xhigh

정합된 피부를 같은 `AnatomySceneRoot`에 한 번 로드하고 기존 레이어 버튼 묶음에 **피부**만 추가한다. 보기옵션 재배치나 전체 UI/카메라 정책 변경은 하지 않는다.

- `skinVisible`은 기존 뼈/근육/신경의 선택 상태와 독립이다. 해부 모드 기존 기본값은 유지한다. 경혈 모드는 첫 진입에서 피부 표시를 제공하되 사용자가 끈 상태를 매 선택마다 다시 켜지 않는다. 모드 종료에서 이전 선택/레이어를 복원한다.
- 불투명 기본 피부는 자연스러운 무광 표현으로 한다. 내부 관찰이 필요하면 기존 투명도 흐름을 재사용한다. 361개 점마다 몸 전체를 반투명으로 다시 그리지 않는다.
- canonical 피부의 triangle+barycentric anchor와 marker glyph를 분리한다. 작은 접촉 표식, selected halo, depth test/법선/최소 z-fighting 오프셋을 사용한다. 피부 OFF가 실제 혈위 좌표를 근육으로 끌어당기는 동작이 되어서는 안 된다. 선택 점의 얇은 국소 체표 단서는 별도 표시하고, 피부 OFF에서 전체 화면에 떠 있는 구체를 남발하지 않는다.
- 고정 reference geometry에 anchor를 두고 LOD용 대응을 보존한다. LOD 교체마다 혈위 authoring을 다시 하지 않는다. 공유 재질·geometry, 기존 lazy load/cache/dispose, 한 frame clock을 사용한다. 새 renderer/인체 복제/상시 OFF update 금지.
- 대표 표식의 피부 접촉과 기존 108 instance의 회귀, skin ON/OFF/불투명/가림·선택·지역 전환을 실제 앱에서 검사한다. 대표점 시험을 전신 361혈 완료로 기록하지 않는다.
- AT21/22의 기존 영역 renderer/editor가 새 canonical carrier를 사용할 수 있게 호환 경로를 확인한다. 이때 14개 영역 데이터 제작까지 진행하지 않는다.

## 점 전체 완성의 순서와 합격 기준

1. Luna 자료 대조는 738316a로 종료됐으므로 재실행하지 않는다. 361 원문 추출과 현재 116개 검증은 구분하며, posture cue는 후보 메모로만 둔다.
2. Sol `skin-fit` → Sol `skin-runtime`.
3. Luna `existing-package-reconciliation`: AT9 74 + AT10 50 위치를 연결하고 기존 108을 회귀한다. 한국어 방법도 기존 카드에 반영한다.
4. Luna AT11 → AT12 → AT13 → AT14 → AT15 → AT16 → AT17 → AT18: 기존 배정은 유지한다. 각 실행은 공통 피부/landmark compiler로 **실제 표시까지** 끝낸다. 새로운 pose engine은 만들지 않는다.
5. Luna AT19: 361 concepts / 670 planned side instances 전수 점검. 실제 표시/선택 가능 수, 방법 반영 수, 위치 등급을 별도로 집계한다. 이름 361개만 있는 상태로 complete 처리하지 않는다.
6. Luna AT23–26: 동일 피부에 14경맥 교육용 영역 연결. Luna AT27: 기존 importer를 재사용해 361혈 한국어 내용 마무리.
7. **마지막 기능 단계:** AT30(Luna) 자세 필요성·방법 전수조사 → AT31(Sol) 공통 자세와 확정된 family 구현. 그 뒤 AT28/29 최종 회귀·성능 검사. UI 대개편은 사용자의 별도 요청으로 한다.

위 순서에서 `AT10 surface-base`라는 옛 다음 지시는 `skin-fit → skin-runtime`을 뜻하도록 대체한다. `locating-posture`는 AT10에서 제거했다. 완료한 AT1–8/20–22/MV2는 재실행하지 않는다.

정지 위치는 근거 있는 landmark·비례 구간·표면 주소로 AI가 작성하고 검증할 수 있다. 피부가 없었다는 과거 이유나 교수 검토 부재만을 복사하지 않는다. 근거 없는 xyz/nearest muscle은 금지한다. 자세에 의존한 특징은 `reference-pose educational location`과 지원되지 않은 동적 자세를 분리한다. 기준 자세에서 신뢰할 위치를 만들 수 없는 **해당 코드만** 남겨 실제 지표를 보강하며, 해부학적 위치를 바꾸거나 모든 점을 대기시키지 않는다.

## 자세는 전수 점 표시 이후

AT30은 **361개 전부**에서 필요/불필요/불명확을 판정한다. 이번 Luna 자료 정리의 54개 자동 cue만 전수조사 결과로 쓰지 않는다. 표지 탐색용 동작, 최종 취혈 자세, 단순 관찰 방향을 구분한다. 거비취지·주먹·개구 등의 실제 수행 순서와 관련 관절/근육을 조사한다. 원문에 없는 정확한 각도를 표준 수치로 만들지 않는다.

AT31은 조사에서 동결한 자세 family만 구현한다. 내부 묶음은 최대 네 범주로 고정한다: `pose-core`(공통 전환과 첫 대표 사례), `upper-limb`, `head-neck`, `trunk-lower-limb`. 불필요한 범주는 조사 근거로 skip하며, 각각 검증된 결과를 다시 처음부터 구현하지 않는다. 가족별 준비/중간/완성/복귀·양측·점/피부/근육/골격 동기화와 빠른 선택/닫기 복원을 실제 화면에서 검증한다. family 하나에 여러 경혈을 연결하며 혈마다 clip/renderer를 복제하지 않는다. scope 검증 완료와 AT31 전체 완료를 구분하되 승인 문서만 반복하는 단계를 만들지 않는다.

현재 static-pose guard를 삭제만 해서 동적 경혈을 지원한 것으로 처리하지 않는다. 피부와 점이 함께 변형되는 계약은 이 단계에서 구현한다. 자동 camera 변경은 별도 UI 요청 전까지 추가하지 않는다.

## 실행 소유와 기록

`침구 LUNA`의 자료 정리가 `738316a`로 종료되고 idle 상태임을 확인한 뒤 EXECUTION의 미래 계획을 병합했다. 그 결과는 116개 요약/비교(82 정합, 22 대안, 10 확인 보류, 2 충돌)이며 learner import와 자세 구현은 0이다. 이 수치는 피부/위치 완성의 대기가 아니라 내용 검토의 정확한 범위다. 현재 다음 단위는 **AT10/skin-fit**이다. [execution-amendment.json](execution-amendment.json)은 적용한 계획 변경과 기준 HEAD를 기록한다. AT9/10 acceptance는 false로 보존하고 AT30/31은 planned로만 추가했다.

다음 Sol은 최신 결과와 r2 정책이 유지되는지 확인하고 해당 피부 산출물만 만든다. 같은 파일을 동시에 커밋하지 않는다. 증거와 원본은 읽기 전용, 소유 변경만 로컬 commit, push/배포 없음. 관련 검사만 수행하고 역사 전체 회귀를 매 경맥마다 반복하지 않는다. 공개 bundle에는 compiler 산출물만 포함하며 PDF/실패 로그/원본 모델/개발 evidence는 포함하지 않는다.
