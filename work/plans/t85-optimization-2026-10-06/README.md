## 작업이 다시 길어지지 않게 하는 방식

- 런타임/공통 가족/등록/상태는 단일 작성자가 담당한다. 병렬 자산 작성은 실제 입력과 소유 디렉터리가 고정된 경우에만 사용자의 별도 승인으로 진행한다.
- 같은 입력의 QC·브라우저 근거는 재사용한다. geometry나 좌표가 바뀐 패키지만 재검증한다. 전체 suite는 최종 통합 또는 실제 회귀 때 수행한다.
- 한 실패를 수리할 때 실패 primitive/관통/방향을 지정하고 새 수정 가설을 기록한다. 같은 실패의 전체 후보 재검색·원장 재작성으로 반복하지 않는다.
- 한 수리 시도가 60–90분 동안 실제 개선 없이 머물면 그 시도의 측정·실패 위치와 다음 가설을 기록한다. 실패 자산을 등록하거나 콘텐츠 부재로 바꾸지 않고, 독립적으로 가능한 구현을 계속한다. 이는 task를 임의 통과시키는 기준이 아니다.
- 현재 31 MB 몸통 자산의 GPU 변형은 이번에 바꾸지 않았다. 이후 실제 모바일 병목이 확인되면 해당 가족만 정밀도/경량 자산을 검토한다. 단순 품질 저하나 예산 상향을 먼저 하지 않는다.
