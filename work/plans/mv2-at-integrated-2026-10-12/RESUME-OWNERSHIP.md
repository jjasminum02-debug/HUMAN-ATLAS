# 중단된 작업 인수·재개 규칙

2026-10-12 사용자 정정. MV2 및 AT의 ‘기존 변경 보존 / 중복 실행 금지’는 **중단된 같은 작업을 인수하지 말라는 뜻이 아니다.** 실행을 계속하라는 요청은 해당 task의 기존 미커밋 결과를 검토·인수하고 남은 일을 마무리할 권한을 포함한다. 다른 task/원본/사용자 변경을 되돌릴 권한을 뜻하지 않는다.

## 판단 기준

| 관찰 | 올바른 처리 |
|---|---|
| 동일 task 미커밋 코드·후보·evidence가 있음 | 재개할 입력으로 분류하고 diff/hash/검증 범위를 확인한다. 자체 중단 사유가 아니다. |
| start 기록의 HEAD가 현재 HEAD와 같음 | 같은 기준선에서 시작했다는 뜻이다. 다른 실행자가 살아 있다는 증거가 아니다. |
| evidence 수정 시간이 최근임 | 최근 작업 흔적이다. 현재 실행 중인지 확인하는 근거와 구분한다. |
| `ps`/프로세스 목록 권한이 없음 | 이 확인 방법이 불가한 것이다. 프로세스 조회 허가를 새 필수 gate로 만들지 않는다. |
| 해당 thread가 idle/failed/systemError이고 현재 충돌 증거가 없음 | 중단된 작업의 소유 범위를 기록하고 이어간다. 사용자에게 같은 재개 승인을 다시 요구하지 않는다. |
| 같은 unit·같은 경로를 쓰는 다른 thread의 현재 active 실행이 직접 확인됨 | 해당 경로의 중복 쓰기는 피하고 최신 실행 상태를 확인한다. 다른 thread 제목/옛 preview만으로 판정하지 않는다. |
| 읽기 사이 내가 쓰지 않은 동일 소유 파일이 실제로 바뀜 | 알려진 generator/종료 커밋/다른 실행자의 변경인지 대조한다. 실제 충돌 경로만 보류하며 무관한 검토는 진행한다. 설명 안 되는 지속 변경이면 한 번 명확히 확인을 요청한다. |
| 최신 EXECUTION·최종 evidence·커밋에서 unit 완료가 확인됨 | 옛 next 프롬프트를 실행하지 않는다. ‘MV2 다음 한 묶음’ 요청이면 최신 다음 unit, 특정 완료 unit만 요청했다면 완료 확인 후 멈춘다. |

앱 상태가 안 보인다는 이유만으로 동시 실행을 추정하지 않는다. 확인 도구가 부족할 때는 실제 현재 파일/커밋/기록과 변경 guard를 사용한다. 새 락 서비스·heartbeat·승인 체계는 만들지 않는다. 같은 애매한 상태를 반복 보고하며 작업을 끝내지 않는다.

## 재개 절차

1. 최신 HEAD, index, 해당 EXECUTION record·최종 report·evidence를 함께 읽는다. 역사 start 기록·폴더 이름·후보 번호는 완료 판정이 아니다. 소유권 확인 후에도 최종 상태를 한 번 더 읽어 이미 끝난 unit을 중복 시작하지 않는다.
2. 변경을 `이번 task의 인수 가능한 WIP / 다른 사용자·task 변경 / 원본·역사 freeze`로 나눈다. 관련 기존 WIP의 diff/hash를 기준선에 기록하고 그대로 이어간다. reset/clean/stash로 깨끗한 checkout을 만들지 않는다.
3. 코드와 입력 hash가 검사 기록과 같으면 그 검사를 재사용한다. 기록만 남은 실제 앱 QA나 변경된 입력은 필요한 범위에서 직접 검증한다. 타인의 검사를 이번 실행자가 재실행했다고 쓰지 않는다.
4. 필요한 최소 수정 → 빠진 검증 → 최종 report/evidence → 해당 EXECUTION 반영 → sync/--check → task 소유 변경만 로컬 커밋까지 진행한다. 해당 task로 인수한 기존 WIP도 선별 포함할 수 있다. 새로 작성한 줄만 소유 변경이라고 좁게 해석하지 않는다.
5. 공유 파일에 무관한 WIP가 섞였으면 hunks로 분리한다. 분리하기 어려운 그 파일은 제외·정확히 보고하고 가능한 나머지 작업을 마무리한다. 다른 사람의 staged 변경을 해제하거나 함께 커밋하지 않는다.
6. 한 task/unit 완료 후 멈춘다. 실제 실패·입력 부재는 구체적인 실패 항목으로 남기며, ‘미커밋/최근 변경/프로세스 조회 불가’만으로 partial/blocked를 만들지 않는다. 카메라/UI 보류와 공개 권리/human review의 분리는 계속 유지한다.

## 이번 사례의 확인 결과

확인 시점에는 ‘침구 SOL’과 ‘침구 LUNA’의 마지막 turn이 모두 종료돼 있었다. Q02의 최종 기록과 코드·EXECUTION은 **`5b51ff627ea048ee4d0c0f9e526a46268d96d094`**에 커밋됐다. Q01 학습 표현도 앞선 `2d182a6fcce068409c804f4e7391f607c14a3b20`에 있다. 이는 현재 기록/커밋 확인이며 이번 문서 작성자가 동작 QA를 재실행한 것은 아니다.

따라서 사용자가 인용한 ‘Q02 미커밋·다음 Q02’ 상태로 재개하면 안 된다. 현재 다음은 **MV1-Q03-biceps-lateral-contour-and-visibility**이며 Q03/Q04/Q05 총 3묶음·31매핑이 남았다. 이 수치는 후속 실행마다 최신 record로 다시 확인한다. [수정된 Q03 실행 프롬프트](NEXT-MV2-Q03.md)를 사용한다.
