# 이름·신경·카드·부위 탐색 개선

2026-10-06 사용자 요청에 대한 실행 계획이다. 이번 작성은 계획과 고정 검토 입력 준비이며 앱 수정이나 해부학 검토 합격 기록이 아니다. 현재 T40은 completed/passed, NEXT의 다음 번호는 없다. 새 번호를 발급하거나 기존 T40/T66/T85 판정을 변경하지 않는다.

## 현재 확인한 문제

- App.tsx는 tab을 구조로 초기화하고 일반 select/navigate 때 구조로 되돌린다. 다만 popstate는 탭을 되돌리지 않는다. 근육 MotionLearningPanel은 탭 바깥에 있고 기능 탭에도 별도 동작 선택기가 있어 선택 UI가 중복된다.
- .motion-action-picker와 .learner-action-picker가 flex-wrap 배열이다. 단순 세로 CSS 변경만으로 중복 선택기 문제가 해결되지는 않는다.
- ‘주변 구조’는 posture_observation에 붙는 분류다. 선택 근육의 실제 작용을 뜻하지 않는다. 이 관찰 기능을 주작용 목록과 분리하되, 운동 장면에 필요한 주변 뼈·근육은 보존한다.
- study-sidebar 전체에 overflow:auto가 있어 부위 버튼도 구조 목록과 함께 위로 사라진다. 검색 중에는 region-grid를 숨긴다. 부위 선택기는 검색/긴 목록과 독립해 항상 접근 가능해야 한다.
- 실제 5180 전달 앱에서 외복사근의 구조 기본 선택, 탭 위 재생 패널, 기능 탭의 추가 선택기를 확인했다. 신경 관계의 정확성이나 전체 근육 이름의 정확성은 이번 계획 단계에서 판정하지 않았다.

## 고정 입력과 범위

run-manifest.json과 input-snapshot/을 실제로 만들었다. 배정을 기다릴 필요가 없다. 기준은 T40의 local-20261006032053779-deedfed2 전달본이고, 관련 신경 JSON과 두 카드 UI 파일의 현재 hash가 당시 sourceDependencies와 일치함을 확인했다.

- 근육 표면 행 472: learner 462, inspection 10. 조사에는 모두 포함하되 inspection을 학생 지원으로 승격하지 않는다. 전체 근육 target은 429이며 표면 수와 별도다.
- 신경 표면 195, 원본 이름 묶음 98, 설명 concept 행 98, 운동근 관계 18행. 98을 독립 해부학적 신경 수로 단정하지 않는다.
- 전수 검토는 각 행의 판정·필요한 수정·미확정을 빠짐없이 기록한다는 뜻이다. 모든 신경의 새 지배 관계나 미제공 형상을 만들어야 종료한다는 뜻이 아니다.

## 실행 순서

1. **01-ui-card-region.txt**: 구조/기능 카드, 단일 세로 동작 선택기, 고정 부위 선택기를 직접 구현한다.
2. **02-nerve-review.txt**: 신경→근육 매칭과 신경 설명을 함께 검토한다. 두 내용의 근거가 겹치므로 한 담당자가 처리한다. 공통 데이터는 수정하지 않고 정확한 수정안을 만든다.
3. **03-muscle-names-review.txt**: 전체 근육 이름 세 필드·별칭·part/side를 검토하고 수정안을 만든다. 공통 데이터는 수정하지 않는다.
4. **04-integrate-and-deliver.txt**: 02/03 결과를 실제 데이터/선택/강조/카드/검색에 반영하고 최종 검증 및 새 로컬 전달본을 만든다.

완전 직렬이면 01 → 02 → 03 → 04. 권장 병렬은 01 완료 후 **02와 03을 별도 대화에서 동시에 실행**, 둘 다 종료 후 04를 단일 작성자로 실행한다. 자동 agent/thread 생성은 없다. 한 대화에서 할 경우 각 파일 종료 뒤 다음 파일을 사용자가 입력한다.

각 단계는 자기 보고서 하나와 수정안/검증 파일을 남긴다. 전체 suite·빌드·PNG는 단계마다 반복하지 않는다. 최종 typecheck/build와 전달 검증은 04에서 한 번 하고, 중간에는 관련 검사와 실제 변경 흐름만 확인한다. 02/03은 runtime을 쓰지 않으므로 공통 파일 충돌이나 서로의 결과 대기를 만들지 않는다.

큰 JSON은 스크립트로 필요한 필드/예외/소집계를 조회한다. 전체 JSON을 대화에 출력하거나 표면별로 같은 문헌 검색을 반복하지 않는다. 고정 muscle target 입력은 용어/분류/side/parent 범위 필드만 포함하며, 상세 과거 근거는 manifest에 hash를 기록한 원래 target-scope-t96.json을 필요 시 참조한다.

## 목표 화면

근육 이름 → 구조/기능 탭(기본 구조).

- 구조: 기시, 정지, 관련 뼈, 신경 관계 등 현재 지원 설명.
- 기능: 실제 근육 작용을 한 줄에 하나씩 세로 나열 → 선택한 작용 설명 → 단일 ‘움직임으로 이해하기’와 관절/진행 조절. 미지원 시범은 글 설명과 짧은 상태 안내.
- 수동 자세 시범: 필요 시 ‘자세에서 관찰하기’를 펼쳐 접근. 근육 작용과 섞거나 라벨만 바꾸어 승격하지 않는다.
- 부위 탐색: 상단에 고정된 ‘부위 탐색 · 현재 부위 ▾’ 버튼 → 전신 + 기존 12부위. 클릭/키보드/터치를 기본으로 하고 마우스 hover는 보조다. 아래 구조 목록만 스크롤한다.

player를 중복 생성하거나 탭 변경으로 새 scene/clock을 만들지 않는다. 재생 중 탭 이동의 중단/부드러운 복원은 기존 controller로 처리한다. 신경의 ‘관련 작용 보기’처럼 명시적 기능 이동은 기능 탭으로 열고, 일반 근육 선택/좌우 변경/뒤앞 이동은 구조 기본값을 적용한다.
