# T70 — 전신 source 후보 범위와 최소 통합 계약 보완

R15 보완 삽입 · 담당 Sol High · 선행 T55/T69 실제 보고서와 T50–T55/T69 코드 검토 · T56 이전

## 범위

BodyParts3D Release 4.0의 추적 중인 공식 metadata와 기존 T51/T52–55 산출물을 읽어 새 revision의 source 후보·첫 시범 제품 최소 목록을 만든다. IS-A 뼈/근육 root closure와 PART-OF/compound/근육 part 원문 관계를 구분한다. 기존 T52–55를 하나의 source ID/node/frame/pose 계약으로 연결하고 T69/T54 좌우 보류와 T53 빈 header identity를 learner 선택 제한으로 전파한다. 기존 원본·freeze·GLB는 덮지 않는다.

## 산출물

- `atlas-data/manifests/bodyparts3d-r4-t70/`: 제품 첫 시범 목표 정책, source closure/누락 목록, T52–55 통합 manifest.
- `atlas-data/tools/build_bodyparts3d_r4_t70_scope.py`와 전용 독립 회귀 검사.
- `work/evidence/T70/`, `work/reports/T70.md`, 현재 STATUS/R15 registry 정합, T56 실제 입력에 맞는 명세 수정.
- 다음 최대 10개 source 요소 취득 task의 정확한 ID·batch·실제 render 합격 기준.

## 필수 합격

1. 공식 metadata에서 뼈 root 203, 기존 지역 배정 168, 기존 패키지 밖 35를 재계산하고 35개 ID를 명시한다. 이 값은 canonical 전신 근육·뼈 분모가 아니다.
2. 대퇴직근·대흉근 부분과 흉골 compound의 원문 FMA/FJ·부모 관계를 실제 index와 대조한다. 첫 시범 제품 목표 선택은 source 분류와 별도 revision이며 없는 source를 만들지 않는다.
3. T52–55 고유 source node 493개를 두 중복 node 없이 연결하고 package hash, frame/pose, 기존 learner ID를 보존한다. T69/FJ2742·FJ2754, T54/FJ1469·FJ1469M, T53 빈 header 8개를 정확히 보류한다. 해당 mesh는 로컬 QA 원본 상태로 남되 학습용 좌우 정답·카드·선택으로 승격하지 않는다. 전체 사람 검토를 독립 개발의 전역 조건으로 두지 않는다.
4. 새 revision은 원본 및 역사 freeze와 구별된다. 실패 주입 검사에서 보류 누락, 중복 node, 존재하지 않는 LOD 승격을 거부한다. 현행 T56은 실제 단일 source LOD를 인정하도록 고치되 필요 시 추가 LOD는 측정 후 별도 자산 작업으로 결정한다.
5. 대량 OBJ 취득, 새 GLB 제작, learner UI, 운동/rig, 자동 배포는 수행하지 않는다. 미취득 source ID는 다음 bounded task에 넘긴다.

## 보존·검증·Git

시작 HEAD/status와 입력 hash·OpenSim_Models 상태를 기록한다. source/metadata/기존 패키지를 읽기 전용으로 사용한다. 새 revision의 재생성·source/index/hold 검증, 관련 기존 회귀, 웹 typecheck/build를 실행하고 결과·한계를 보고한다. 기존 사용자 WIP가 섞인 STATUS/registry/T56 명세는 작업트리에서 정합시키되 전체 파일을 임의 stage하지 않는다. task 소유 변경만 staged diff 확인 후 로컬 commit한다. push·배포·다음 task 자동 실행 금지.
