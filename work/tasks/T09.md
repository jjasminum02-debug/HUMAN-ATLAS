# T09 — 부착부 annotation 검토 도구

## 목적과 선행 조건

T08의 정적 3D viewer에 검토 전 annotation 작성 도구를 연결한다. T09는 실제 기시·정지 위치를 채우는 데이터 입력 단계가 아니라, 점·선·면 후보를 안전하게 만들고·수정하고·내보내는 도구 단계다.

선행 자료: 설계 `00`–`04`, T05/T08 명세·결과와 실제 T07 GLB/manifest, T03 `SpatialAnnotation` schema 및 validator. 기존 카탈로그의 `instances`는 0개이므로 실제 Atlas `SpatialAnnotation`으로 승격할 instance 참조가 없다. UI/JSON 초안은 이를 숨기지 않고 `instanceId: null`, `reviewState: draft`로 격리한다. Canonical T05 claim/attachment 및 T03 schema는 수정하지 않는다.

## 작업 범위

- `atlas-web/**`: 검토 모드, point/polyline/surface patch 작성·편집·삭제, source attachment/claim 연결, local persistence, JSON import/export, overlay drawing.
- `atlas-data/schemas/annotation-draft-exchange.schema.json`: T03 canonical `SpatialAnnotation`과 구분되는 로컬 draft exchange schema.
- `work/tasks/T09.md`, `work/reports/T09.md`, `work/evidence/T09/**`, `work/DECISIONS.md`, `work/STATUS.md`.
- synthetic-only fixtures와 validator tests를 사용한다. 실제 catalog에 annotation을 쓰거나 anatomy review를 완료 상태로 바꾸지 않는다.

## 완료 기준

1. 점·선·면을 모델 표면에 놓고, 기존 도형을 편집·삭제할 수 있다. world/frame 좌표는 카메라가 아닌 T07의 asset frame에 저장한다.
2. draft는 선택한 실제 T05 attachment 및 description claim ID/evidence ID를 참조하고 UI에서 source 문장을 확인할 수 있다. 이 연결과 mesh 선택은 provisional이며 anatomical correspondence 증거로 승격하지 않는다.
3. 로컬 저장과 JSON export/import가 재접속 뒤 도형을 보존한다. 잘못된 JSON은 현재 저장 자료를 덮어쓰지 않는다.
4. 좌우 또는 asset ID/revision/hash mismatch import를 거부한다. 기존 로컬 도형의 topology hash 변경은 `stale`로 표시하고 렌더하지 않는다. surface triangle index도 현재 topology 기준으로 확인한다.
5. `reviewed` 상태를 입력할 수 없고 `instanceId`가 없는 draft는 canonical Atlas schema에 적합하다고 표현하지 않는다.
6. positive/negative synthetic fixtures, typecheck/build, 실제 브라우저 동작·console, 보존 전후 증거를 남긴다.

## 범위 밖

실제 해부학적 부착면 확정/파일럿 좌표 채택(T10), anatomy review 승격, 근육 포즈 변형, OpenSim 연결·수정, 원본 OBJ/GLB 수정, 공개/배포, 환자 진단·치료·침 시뮬레이션은 하지 않는다.
