# Explicit landmark anchor input, version 2

This is the common offline input contract, not a set of accepted acupoint positions.
The TypeScript contract lives in `atlas-web/src/viewer/acupoints/anchorCompiler.ts`.
The runtime and migration contracts extend the existing `schema.ts` and reuse
`anchorAdapter.ts`. Carrier geometry is registered once; no new scene or body is created.

## Required input

`RuleDocument` contains `schemaVersion: 2`, a frozen runtime `context`, `units`, and
`inputs`. Each unit owns its immutable original location text/source references,
side, pose, AI/human author, professor review, rule, and named anatomical annotations.
`inputs.domain` separates `real_input` from `technical_fixture`; it must agree with
each unit's scope. A fixture renamed to a point code remains a fixture.

Each landmark supplies a named anatomical annotation, a native geometry key and
triangle/barycentric address, a corresponding carrier address, and evidence. The
compiler replays both hashes and addresses. Bounds extrema, nearest results and
mirrors are not anatomical annotations. Surface correspondence is an explicit
input with a recorded tolerance, not a nearest search. Tolerance is a replay
condition and does not establish anatomical precision or skin thickness.

Evidence records preserve their original text, source locator, author, side,
frame, pose, carrier hash, and code. `confirmed/anatomical_correspondence` means
the input author has actually compared the cited anatomical relation and native
surface/landmark; it must never be generated by changing the status of a bounds
proposal. The compiler validates explicit evidence inputs; it is not a general
anatomical landmark detector or a substitute for reviewing those annotations.

## Rules

- `landmark`: the explicit landmark's supported surface address.
- `B-cun`: numerator/denominator along an explicitly supplied connected surface
  path between two annotated landmarks. Source evidence must match the denominator.
- `F-cun`: model-specific annotated finger-cun reference span, its source-defined
  cun value, and an explicitly directed supported surface path. It is not a fixed
  millimetre conversion and cannot extrapolate beyond the supplied surface.

Each path segment stays in one registered triangle; transitions require shared
topology and matching endpoints. No bridges across disconnected fingers, body
regions or absent mucosa are synthesized. The output is a fixed barycentric
address, resolved by the existing adapter, valid only in the frozen source pose.

## Judgment and migration

Technical replay, educational approximation, AI authorship, professor review,
local source rights and public redistribution remain separate. Local eligible
positions require all location checks and meaningful evidence. AI authorship is
retained and is not a permanent exclusion. Professor review and public release
remain independent; local source rights holds still block the affected unit.
The educational grade never claims exact skin/clinical location.

`migratePlacementDocument` adds a V2 assessment without changing any V1 point,
AI, missing, source, or review field. Legacy positions without explicit verified
rules remain unresolved, even when old flags say verified. Repeating migration is
idempotent. Historical source files are not overwritten.

`productInstances` is a metadata filter; runtime callers use the asynchronous
`projectLearnerInstances`/`resolveLearnerProjection` to check actual geometry hash,
frame, dataset, static pose and cancellation. Compact projection retains author,
input hash, educational grade and independent review/public state, while full
source text and failed history stay offline. Neither projection imports fixtures.

## Run and resume

From `atlas-web`, using the installed Node runtime:

```sh
node --experimental-strip-types scripts/compileAcupointAnchors.ts --input rules.json --out ../work/evidence/<owned-unit>
node --experimental-strip-types scripts/compileAcupointAnchors.ts --input rules.json --out ../work/evidence/<owned-unit> --resume
```

Raw input editions are stored byte for byte under `inputs/<sha256>.json`.
Failed attempts are immutable content-addressed files; a checkpoint reuses only
successful units with the same rule, relevant evidence, actual geometry bytes and
compiler version. Failed units retry independently. Related changed input invalidates
its own checkpoint. Inspect `ledger.json`, `receipt.json`, and
`runtime-projection.json`; never count a failed/fixture unit as an accepted point.

AT5 engineering cases are in `work/evidence/AT5/`. Existing actual LU inputs remain
22 unresolved positions and zero local learner instances. Their position authoring
is the separately assigned AT6 task; the fixture examples are not that dataset.
