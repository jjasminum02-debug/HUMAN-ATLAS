# 경혈·경맥·경근 영역 학습 — 2026-10-11 설계

상태: **설계 제안 완료, 구현 미착수**. 사용자의 이번 요청으로 역사 T68의 별도 설계 요청 조건은 충족되지만, T68 또는 후속 구현의 완료·승인을 뜻하지 않는다. 현재 EXECUTION/NEXT의 실행 순서는 변경하지 않는다. 이 문서의 AC1–AC5는 새 숫자 task가 아니라 이 기능의 다섯 구현 단위다. 실행 프롬프트는 [별도 문서](../../work/plans/acupoint-channel-2026-10-11/PROMPTS.md)에 있다.

## 1. 목표와 첫 납품

현재 HUMAN ATLAS의 인체 모형에서 경맥을 선택하고, 체표의 경혈과 경로를 따라가며, 경근과 학습 영역을 구별해 관찰한다. 다른 앱이나 검은 배경의 별도 뷰어로 이동하지 않는다. 이번 요청에서는 앱 코드·보기옵션·기존 UI를 변경하지 않는다. 실제 구현에서도 먼저 필요한 진입점과 기능만 붙이고 전체 UI 재설계는 나중에 한다.

첫 납품은 **오른쪽 수태음폐경 LU1–LU11의 실제 모델 위 학습 흐름**이다. 목록이나 schema만 만들고 완료 처리하지 않는다. 체표 기준 확인, 11개 점 선택, 경로 표시, 카메라 안내, 설명 연결, 영역 표시 기술을 같은 장면에서 검증한다. 영역의 실제 내용이 미확정이면 경혈·카메라 기능의 기술 완료와 영역 콘텐츠 미완을 따로 보고한다.

표기 기준: LU1 중부 → LU2 운문 → LU3 천부 → LU4 협백 → LU5 척택 → LU6 공최 → LU7 열결 → LU8 경거 → LU9 태연 → LU10 어제 → LU11 소상. 태연은 LU9이고 마지막은 소상이다. [KMCRIC 표준경혈 DB](https://www.kmcric.com/database/acupoint/LU), [WFAS 표준명·코드 자료](https://www.wfas.org.cn/a47122.html)와 대조했다. 상세 위치 문장은 사용자 지정 교과서 판본과 이후 대조한다.

## 2. 점·선·면·설명은 독립 자료

| 개념 | 그래픽 | 저장·변경 단위 |
|---|---|---|
| 경혈 | 체표의 점, 선택한 점 이름 | 코드·명칭·취혈 설명과 모델 위 좌표를 분리 |
| 경맥 | 체표 경로와 분지 | 번호순 학습 경로와 전통적 전체 유주를 구분 |
| 경근 | 해당 근계의 주행·결취·분지 등 교재 표현 | 경맥 선을 굵게 만든 것으로 대신하지 않음 |
| 학습 영역 | 인체 표면에 얹는 색 면 | 교과서·교수 설명·학습용 해석 중 어느 것인지 명시 |
| 관련 근육 | 근육 선택·강조 | 근육과 경근/영역은 다대다 관계, 근거와 해당 부분을 기록 |
| 수업 연결 설명 | 영역과 경혈 사이 학습 연결 | 근처에 있는 점과 교수님이 연관 지어 설명한 점을 별도 관계로 저장 |

첨부 그림은 색 면을 보여주는 **시각 참고**다. 그림만으로 경근·피부·경맥 영역 중 정확히 어떤 이론의 경계를 그린 것인지 확정할 수 없다. 출처와 교수님의 해석이 확인되기 전에는 `학습 영역`으로 취급한다. 신경 지배영역·피부분절과 합치지 않는다. WHO 경혈 위치 표준을 색 영역의 경계 근거로 확대 해석하지 않는다.

“위경 영역이 너무 넓다”는 피드백은 영역 경계의 버전을 수정한다. ST 경혈 좌표나 경맥 선, 원래 근육 geometry는 그대로 유지한다. 선에서 일정 반경으로 색을 퍼뜨리거나 가장 가까운 경혈에 따라 전신을 분할하는 알고리즘을 해부학 근거로 쓰지 않는다. 영역은 겹칠 수도 있고 비어 있을 수도 있다.

교수님의 소장경·방광경 사례는 이후 `lecture_association`에 저장할 수 있다. 발화에서 불분명한 혈명·술기명은 원문을 보존하고 확인 전 연결하지 않는다. 영역을 선택했다고 특정 혈의 치료 효과를 자동 결론 내리거나 자침 위치·깊이·방향을 추천하지 않는다. 이번 범위는 관찰·학습이다.

## 3. 학습자가 경험할 흐름

1. 기존 인체를 보고 있다가 경혈 기능을 켠다. 기존 근육·뼈·신경의 사용자 표시 선택은 보존한다.
2. `수태음폐경`과 `오른쪽`을 선택한다. 오른쪽은 화면 방향이 아닌 **인체 기준**이다.
3. 오른쪽 앞가슴과 팔이 잘 보이는 사선 시점으로 짧게 이동한다. 인체 전체를 회전시켜 좌표계를 바꾸지 않고 기존 카메라만 움직인다. 뒤에서 보고 있었다면 최단 경로와 가림을 고려한다. 고정 yaw 부호를 좌우에 무조건 적용하지 않는다.
4. LU1–LU11의 점과 체표 경로가 나타난다. 처음에는 해당 경맥 전체가 보인다. 선택한 점만 이름을 크게 표시하고 나머지는 작은 점/코드로 유지한다.
5. **`경혈 따라보기`**를 누르면 중부에서 소상까지 차례로 강조한다. 가슴 → 위팔 → 팔꿈치·아래팔 → 손목·엄지 구간으로 카메라를 나누어 이동하고, 매 점마다 화면을 크게 흔들지 않는다. 일시정지·이전·다음이 가능하다.
6. 점을 누르면 같은 옆 패널에 `중부 · LU1`, 소속 경맥, 취혈 위치, 찾는 기준 구조, 교과서 설명이 표시된다. 사용자 자료가 없는 필드는 `설명 준비 중`으로 짧게 처리하며, 확인된 이름까지 비우지 않는다.
7. `영역 보기`를 켜면 해당 학습 영역이 옅은 색으로 나타난다. 경근 자료가 있는 경우에는 별도 `경근 보기`로 주행을 볼 수 있다. 둘을 동일한 내용으로 가장하지 않는다.
8. 따라보기를 끝내면 시작 시점으로 복귀한다. 사용자가 직접 회전하면 자동 진행과 자동 복귀를 멈추고 현재 시점을 존중한다. 명시적 `이전 시점` 조작으로 돌아갈 수 있다.

경맥 선택 시 0.5–0.8초 정도의 전환은 초기 조정값일 뿐 고정 품질 기준은 아니다. `prefers-reduced-motion`에서는 즉시 이동·순차 선택으로 대체한다. 자동 재생은 버튼을 눌렀을 때만 시작한다. 390px에서는 손목 점을 패널 아래에 숨기지 않도록 실제 사용 가능한 viewport 영역을 기준으로 framing한다.

표시 경로가 순서대로 드러나는 효과는 **학습 순서 안내**다. 그 효과를 기의 흐름을 실측한 것처럼 설명하지 않는다. 내행·분지는 외부의 점 11개를 단순 연결한 선과 별도 자료다.

## 5. 가장 먼저 확인할 기술 문제: 경혈을 붙일 체표

현재 점검한 runtime 계약과 source catalog만으로는 **현재 ZA 장면에 정확히 정합된 경혈용 skin carrier가 사용 가능하다고 확인하지 못했다**. 이것은 원본 전체에 피부가 없다는 판정은 아니다. 근육 표면에서 가장 가까운 점을 찍는 것만으로 피부의 경혈 위치를 만들 수 없다.

AC1에서 한 번만 다음 순서로 판정한다.

1. 이미 확보한 source의 피부/외피 후보가 있는지 object ID·실제 geometry·frame·pose·권리를 확인한다. 프로젝트의 기존 목록·compiler를 우선 사용한다.
2. 같은 모델에 맞는 후보가 있으면 단위를 바꾸거나 임의 정규화하지 않고 적용한다. BP3D 모델의 좌표를 ZA에 그대로 옮기지 않는다.
3. 적합한 후보가 없으면 기존 몸에 맞춘 **학습용 체표 carrier**를 만드는 비용과 다른 모델을 정합하는 비용을 비교해 한 가지를 선택한다. 근육 외피를 감싼 대략적 형태는 정밀 취혈 표면이라고 부르지 않는다. 손톱·손목 주름 등 세부 기준이 없는 부분은 표시 한계를 기록한다.
4. 쇄골·흉곽, 팔꿈치, 손목, 엄지의 기준점을 대조하고 LU1/LU9/LU11 세 지점의 전면·사선·측면 결과를 확인한다. 단순히 표면에 붙었다는 사실과 위치 설명에 맞는다는 사실을 따로 검증한다.

carrier는 원래 해부 모델을 대체하지 않는다. 기본 관찰에서는 숨은 위치 기준으로 사용하고, 선택 영역의 색 면만 필요할 때 렌더한다. 근육 모드와 체표 모드를 지원하더라도 같은 정합·카메라를 사용한다. 실제 살갗과 다른 교육용 투명 표면은 간단한 범례로 설명한다.

확정 carrier의 topology를 anchor 전용으로 유지하고, 렌더용 LOD는 따로 낮출 수 있다. LOD마다 triangle index가 달라지는 문제를 런타임 최근접점으로 매번 땜질하지 않는다. 체표 취득/정합에 진짜 입력 부족이 생기면 실패 지점과 선택한 다음 방법을 하나로 남기고, 같은 이름 검색이나 승인 대기 보고서를 반복하지 않는다. 독립적인 schema·UI·카메라 개발은 fixture로 계속할 수 있지만 fixture를 실제 혈위로 공개하지 않는다.

## 6. 자료 계약과 편집 방식

실제 schema 구현은 AC1에서 한다. 아래는 필수 필드 의미이며 제품 좌표나 완성 데이터가 아니다.

| 자료 | 필수 내용 |
|---|---|
| `PointConcept` | `code`, 한글명, 로마자 표기/별칭, 경맥, 표준·교과서 판본, 설명 필드별 sourceRef |
| `PointInstance` | `code + side`, carrier revision/hash, frame/unit/pose, triangle+barycentric 또는 확인된 landmark binding, 위치 확인 근거 |
| `ChannelRoute` | `surface_teaching`/`classical_external`/`internal` 구분, segment·분지·방향·출처, 별도의 학습 point 순서 |
| `SinewPath` | 출처별 주행·분지·결취 표현, 관련 근육/부분의 다대다 관계, 해석 구분 |
| `Territory` | 경맥, `teaching_region`/`cutaneous`/`sinew_projection` 구분, 좌우, carrier hash, 독립 경계 mask와 판본 |
| `LearningAssociation` | 연결 대상, `spatial_context`/`lecture_association` 등 관계 종류, 설명·근거, 아직 확인되지 않은 원문 |
| `Tour` | point 순서, 구간별 camera target·거리·방향, 가림 회피, 정지·복귀 정책 |

취혈 설명과 3D 좌표는 독립이다. 비례촌·손가락촌·해부학적 지표와 적용 자세를 표현할 수 있어야 하고, 모든 `촌`을 고정 mm로 환산하지 않는다. [WHO 2008 표준 서지](https://library.wpro.who.int/cgi-bin/koha/opac-detail.pl?biblionumber=11227&shelfbrowse_itemnumber=11237), [표준 작성 관련 설명](https://pmc.ncbi.nlm.nih.gov/articles/PMC2862941/)을 참고하되 최종 학습 본문은 사용자가 지정한 교과서 판본을 따른다.

좌표·설명·경로·영역은 서로 다른 revision을 갖는다. 기술 검증, 문헌 대조, AI 제안, 선택적 교수 검토, 로컬 표시 권리, 공개 재배포를 별도 기록한다. 과거 task에서 승인하지 않았다는 문구만으로 새 조사·기술 구현을 막지 않는다. 반대로 코드가 움직인다고 위치 검증이나 권리가 생기지는 않는다.

교과서 입력은 사용자가 익숙한 표를 받아 변환한다. 최소 열: `코드 | 이름 | 소속 경맥 | 위치 | 취혈 자세/기준 | 설명 | 교과서명/판/쪽 | 추가 메모`. 원문과 학생용 요약을 따로 보관한다. 위치 충돌만 예외 목록으로 모으고 확인된 이름·일반 설명은 활용한다. 한자 원문이 들어와도 기본 학생용 문장은 한글로 표시한다. 출처는 내부에 보존하고 매 설명 옆에 늘어놓지 않으며 필수 attribution은 기존 안내/라이선스 화면에서 제공한다. 사용자 자료 전체를 공개 저장소에 자동 올리지 않는다.

영역 편집은 개발자용 `/review`에서만 제공한다. 기본은 고정 carrier의 triangle mask/가중치 브러시와 지우기·되돌리기다. 좋은 UV가 실제로 확인되면 UV mask로 export할 수 있지만 둘을 처음부터 중복 구현하지 않는다. 경계 feather는 시각 처리이며 확률·생리학적 확산 폭이 아니다. 위경의 폭 수정 전후를 같은 카메라로 비교하고 변경 구역만 기록한다. 학습 화면에는 JSON 내보내기·검토 상태·task 번호를 노출하지 않는다.

## 7. 공개 프로젝트 조사와 채택 결정

2026-10-11 공식 저장소 README/명시된 LICENSE/NOTICE 기반의 **문서 조사**다. 외부 앱을 실행하거나 좌표를 검증한 결과가 아니다. 사용자가 말한 “Acupuncture 3D”의 정확한 저장소는 아직 특정되지 않았으며 아래는 관련 후보다.

| 후보 | 참고할 부분 | 이번 결정 |
|---|---|---|
| [JICio/tcm-3d](https://github.com/JICio/tcm-3d) | 경혈 overlay, 순차 탐색, 체표 경로 전처리 | 가장 먼저 필요한 함수만 조사할 후보. 본 앱 전체나 술기 도구는 가져오지 않음 |
| [eb-barry/acupuncture-3d-authoring](https://github.com/eb-barry/acupuncture-3d-authoring) | 체표 곡선·점 편집, undo/redo, schema export | 저작 도구의 UX 참고. 바로 코드/데이터를 복사할 대상으로 확정하지 않음 |
| [Antonio-Abrao/acu-master](https://github.com/Antonio-Abrao/acu-master) | Three.js 경혈 조회와 좌표 편집 방식 | 구형 독립 뷰어. 현재 앱을 교체할 이점이 적음 |

JICio는 [코드 MIT, 모델 별도 CC BY 4.0](https://raw.githubusercontent.com/JICio/tcm-3d/main/LICENSE)을 명시한다. README는 좌표가 전문 검토를 마치지 않았으며 표면 접촉이 표준 위치 정확성을 보장하지 않는다고 밝힌다. 따라서 좌표를 기준 정답으로 채택하지 않는다. 경혈 수가 다른 판본도 있으므로 그 목록을 사용자 교과서에 무조건 덮어쓰지 않는다.

eb-barry 도구는 모델을 높이 3 scene units로 정규화한다고 설명한다. 현재 metre 좌표계에 JSON을 그대로 넣을 수 없다. 확인한 루트 목록에는 앱 코드 LICENSE가 드러나지 않았으며 [third-party notices](https://raw.githubusercontent.com/eb-barry/acupuncture-3d-authoring/main/THIRD_PARTY_NOTICES.md)는 해당 프로젝트에 대한 경혈 목록 이용 허락과 모델별 출처를 적는다. 이 문구가 우리 프로젝트의 재사용 허락까지 보장한다고 해석하지 않는다. Antonio 저장소에는 [GPL-3.0 LICENSE](https://github.com/Antonio-Abrao/acu-master/blob/master/LICENSE)가 있다. 실제 코드를 도입한다면 선택 revision의 적용 조건과 현 프로젝트 배포 방식을 별도 확인한다.

결론: **기존 HUMAN ATLAS + 작은 overlay + 선별한 공개 코드/알고리즘 참고**가 우선이다. 외부 완성 앱을 iframe으로 넣거나 두 인체를 겹치는 방식은 카메라·선택·좌표·용량 문제를 늘린다. 코드 채택 시에만 commit SHA·원본 파일·수정 사항·license notice를 고정한다. 이번 설계에서 외부 코드를 복사하거나 모델을 내려받지 않았다.

## 8. 다섯 구현 단위와 합격 기준

| 단위 | 구현 범위 | 끝났다고 볼 증거 |
|---|---|---|
| AC1 체표와 좌표 연결 | 기존 source 조사 1회, carrier 결정/정합, 공통 schema·adapter, LU1/9/11 3점 prototype | 동일 모델의 세 지점 실제 화면, 단위·좌우·자세·anchor 재현, 입력 권리 판정, 없으면 구체적 실패 지점 |
| AC2 폐경 학습 완성 | 오른쪽 11점, 선택 카드, 구간형 카메라 tour, 취소/복귀, 왼쪽 자료 확장·검증 | 같은 canvas에서 11점 끝까지 탐색, 원래 선택/시점 복원, 좌우 혼동 없음. 왼쪽은 단순 mirror를 검증 없이 확정하지 않음 |
| AC3 영역·경근 표현 | mask 편집/표시, 경근 분지 자료 형식, 폐경 및 위경 폭 수정 사례 | 경계 변경이 점/선에 영향 없음, 전면·측면·후면 점검, 겹침 지원, 교수 피드백 반영 가능한 버전 비교 |
| AC4 교재와 경맥 확대 | 교과서 표 import/대조, 동일 renderer로 나머지 11 정경의 점·경로·준비된 경근/영역 확장 | 경맥별 점 목록·좌우·분지·설명·표면 상태 전수 표, 확인된 것만 표시, 누락은 정확히 계수 |
| AC5 통합 품질 | 반응형·접근성·성능·회귀와 데이터 예외 정리 | 실제 390/1024/1440 화면, orbit/점 선택/전환/해제, network·GPU 비용·leak 측정 |

AC1–AC2의 공통 좌표·카메라 계약은 복잡한 설계 담당자가 먼저 고정하고, 반복적인 자료 변환·확대는 사용자의 기존 Luna Max 흐름으로 진행할 수 있다. 모든 경혈마다 task나 loader를 만들지 않는다. 한 번 실행에 경맥 단위 내부 checkpoint를 남기되 다음 경맥마다 전체 앱 검사·재조사를 반복하지 않는다. 새로운 버그·새 geometry가 있을 때 관련 검증을 넓힌다.

12정경의 기술 확대와 모든 설명/영역 콘텐츠 완성은 다르다. **임맥·독맥, 경외기혈은 자동 범위에 포함하지 않는다.** 필요할 때 같은 schema에 추가한다. 임독맥을 포함하는 361혈 목록과 12정경만의 범위를 혼용해 완료율을 만들지 않는다. 교재를 나중에 받아도 AC1–AC3 공통 기능은 진행할 수 있다. 다만 출처 미확정인 영역의 모양 자체는 완료라고 하지 않는다.

## 9. 가볍게 유지하는 방법과 검증

- 기능을 켤 때만 모듈과 선택 경맥의 compact data를 로드한다. 레이어를 끄면 tour 구독·point hit target·자체 GPU resource를 해제한다. 기존 shared anatomy geometry/material은 dispose하지 않는다.
- 점은 instancing 또는 공유 geometry/material, 선은 경맥별 묶음으로 그린다. 361개 DOM 이름표를 상시 렌더하지 않는다. 영역 mask는 선택 범위만 로드한다. texture GPU 비용도 geometry와 따로 계수한다.
- 지오데식/표면 투사·영역 생성은 authoring/build 단계에서 수행한다. 매 frame 전체 인체 raycast나 전역 최근접 탐색을 돌리지 않는다. 피부 pick 가속이 실제 측정상 필요할 때만 BVH 도입을 검토한다.
- 개발 evidence·실패 기록·교재 원본·편집 이력은 `work/`와 별도 source 저장소에 둔다. public/static bundle에는 채택된 runtime projection만 포함한다. 초기 앱에 경혈 JSON과 source 문서가 들어가지 않았는지 build/network로 확인한다.
- 기존 예산을 조용히 올리지 않는다. AC1에서 carrier 포함 peak 비용을 측정하고 남은 예산 안에서 LOD를 정한다. AC5는 같은 기기의 OFF/ON 비교, frame time p50/p95, draw calls, triangles, GPU 추정 bytes, 첫 표시 시간을 기록한다. 30회 on/off·경맥 전환 후 자원이 계속 증가하지 않아야 한다. 기능 OFF 상태에서 새 모듈 요청·상시 업데이트가 없어야 한다.
- 좌우·코드 순서·자료 누락·hash 불일치·stale anchor·취소 race는 자동 검사한다. 손목/엄지와 가슴의 위치·가림·좌우는 실제 모델에서 비교한다. 점이 찍히거나 테스트가 통과한 것만으로 취혈 정확성 합격을 선언하지 않는다.
- 보기옵션 구성·로딩 문구·홈 디자인은 이번 확장의 별도 범위가 아니다. 기존 사용자 선호를 유지한다. 추가 UI는 선택한 경혈 기능 안으로 한정한다.

## 10. 후속 입력과 Git

사용자가 나중에 제공할 자료는 교과서 제목/판본과 해당 내용, 교수님이 의도한 영역의 수정 기준, 불명확한 강의 혈명이다. 지금 설계를 위해 이를 다시 입력할 필요는 없다. 새 기능의 좌표·카메라·편집 구조부터 만들 수 있다.

각 AC 단위는 한 번에 하나만 실행하고 해당 범위가 검증되면 로컬 커밋한다. 기존 사용자 WIP와 원본/OpenSim_Models/T13 drafts를 보존한다. 권리·좌표 미해결은 정확한 대상만 남기고 기술 완료와 콘텐츠 미완을 분리한다. 새 번호를 계속 발급하지 말고 같은 AC 단위에서 구체적 결함을 수정한다. push·배포·환자 진단·치료·자침 시뮬레이션은 별도 요청 없이 실행하지 않는다.
