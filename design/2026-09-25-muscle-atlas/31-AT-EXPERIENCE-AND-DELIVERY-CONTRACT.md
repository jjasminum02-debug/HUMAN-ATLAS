# AT 그래픽·학습 UI·작업 인수 계약

2026-10-11 사용자 요청에 따른 계획 정정. 구현 결과가 아니며 AT2 진행은 유지한다. [30 설계](30-AT-361-POINTS-AND-TERRITORIES.md)와 [실행 안내](../../work/plans/acupoint-at-2026-10-11/START-HERE.md)의 공통 계약이다.

## 1. 작업 크기와 완료의 의미

시간은 설계자가 범위를 나누는 참고일 뿐 실행 중단 조건이 아니다. 각 task는 명시한 입력, 한 묶음의 산출물, 관찰 가능한 합격 기준으로 닫는다. 끝낼 수 있는 작업은 끝낸다. 남은 일을 시간 경과로 다음 번호에 넘기거나 미완을 complete로 바꾸지 않는다.

한 task 안에서 작은 함수/자료/테스트를 함께 만드는 것은 정상이다. 반대로 피부 소스 선택·새 전신 조형·위치 추론·카메라 설계·361혈 입력을 한 task에 몰아넣지 않는다. 이미 받은 입력과 공통 도구를 재사용하며 실제 입력 결함 때문에 진행할 수 없으면 해당 부위·코드·원인·시도한 대안만 정확히 남긴다. 이름 검색·과거 승인 상태만 반복 보고하지 않는다.

완료한 AT1은 다시 실행하지 않는다. 진행 중 AT2는 기존 표본/경로 결정을 이어간다. AT2에 이 문서의 후속 화면 구현을 추가하지 않는다. 기존 AT1/AT2 결과·개념 원장·AC 역사 evidence는 수정하지 않는다. AT1/AT2 record에 남은 estimateMinutes는 역사 계획값이며 타이머가 아니다.

## 2. 사용자가 밟는 흐름

`기존 인체 관찰 → 경혈 진입 → 경맥 선택 → 좌우 선택 → 점/설명 관찰 → 경맥 따라보기 → 영역 함께 보기 → 기존 해부 관찰로 돌아가기`를 같은 화면에서 제공한다.

- 진입: 기존 레이어/기능 진입부에 `경혈` 하나를 추가하거나 기존 진입을 재사용한다. 기존 보기옵션의 순서와 레이아웃을 다시 바꾸지 않는다.
- 경맥: `수태음폐경 · LU`처럼 학습 가능한 명칭과 코드를 함께 보여준다. 14개를 복잡한 하위 메뉴로 나누지 않고 검색 가능한 간결한 선택 목록으로 제공한다.
- 좌우: `양쪽 / 오른쪽 / 왼쪽`. 인체 기준임을 처음 사용 시 짧게 안내한다. 임독맥에서는 좌우 조작을 숨기고 정중임을 표시한다. 경맥을 바꿀 때 유효한 이전 side를 유지한다.
- 표시: 경혈 화면 안에서 `경혈 · 경로 · 영역` 세 표시만 조절한다. 점/선은 기본 ON, 면은 사용자가 정한 상태를 유지한다. 기존 anatomy layer-off를 강제로 켜지 않는다. 자료가 없는 면은 가짜 면으로 채우지 않는다.
- 범위: 기본은 선택 경맥. `전체 경혈`은 명시적으로 전환할 수 있고 이때만 전체 점을 표시한다. 색 영역의 전체 비교는 별도 표시 모드로 두어 점 보기와 자동 연동하지 않는다.
- 검색: 코드와 한글명으로 즉시 선택한다. 코드/이름을 함께 보여주고 선택 시 해당 경맥·side·카드가 일치한다. 지도에서 찾을 수 없는 항목은 이유를 짧게 알려주되 내부 상태 이름을 노출하지 않는다.
- 설명: 제목 `중부 · LU1` 아래 소속 경맥, 기본 위치, 확인된 설명 순서. 위치를 읽기 위해 출처/검토/ID를 지나가지 않게 한다. 필요한 법적 출처 표시는 기존 앱 정보에 둔다. 교재가 없으면 빈 탭을 늘리지 않는다.
- 기본 행동: 카드 가까이에 `경맥 따라보기`. 재생 중에만 일시정지·이전/다음·종료가 나타난다. 개별 점 설명을 읽는 중 자동으로 다음 점으로 넘어가지 않는다.
- 보기: 기존 `화면 맞춤`은 현재 선택 경맥/전체 범위를, 기존 `선택 맞춤`은 선택 점과 주변 landmark를 보여준다. 점 하나의 bounding sphere에 과도하게 줌하지 않는다. `관찰 시점` 버튼은 복구하지 않는다.

데스크톱은 기존 패널을 재사용한다. 경맥 선택과 상세를 같은 폭 안에서 전환해 모델이 좌우로 계속 밀리지 않게 한다. 모바일은 접을 수 있는 하단 패널을 사용하되 실제 기존 레이아웃에 최소 변경으로 통합한다. 3D 드래그 영역과 패널 스크롤 영역을 분리하고, 펼친 패널·safe area를 제외한 가시 영역으로 framing한다. 학생 화면에 JSON/export/annotation/review/task 번호를 추가하지 않는다.

## 3. 자연스러운 그래픽의 구체적 기준

### 장면과 상태

같은 AnatomySceneRoot·renderer·카메라·조명·배경을 사용한다. 경혈을 켰다는 이유로 검은 별도 viewer, 새 인체, 근육 삭제/기본 투명화가 생기면 실패다. 선택·layer-off와 사용자 카메라 상태는 각각 보존한다. 기존 CameraSessions 및 tour 생명주기를 재사용하고 두 번째 전역 카메라 관리자를 만들지 않는다.

경맥 변경은 `요청 → 필요한 작은 자료 로드 → 현재 선택과 일치하는 데이터만 적용 → 부드러운 전환` 순서다. 로딩 중에는 원래 해부 모델을 유지한다. 이전 경맥 점을 새 경맥으로 잘못 표시하지 않도록 선택 라벨·자료 commit을 함께 바꾸거나 짧은 영역 내 로딩 상태를 보여준다. 빠른 연속 선택은 마지막 요청만 적용하고 이전 fetch/animation을 취소한다. 카메라 이동을 로딩 완료마다 중복 실행하지 않는다.

### 카메라와 따라보기

모델 자체를 돌리지 않고 카메라를 천천히 이동해 경혈 anchor/frame을 유지한다. 오른쪽 폐경 선택은 환자 오른쪽 흉부와 팔이 읽히는 사선 구도를 기본 후보로 삼되, 이미 잘 보이는 시점이면 불필요하게 회전하지 않는다. 화면 좌우로 해부학적 좌우를 판단하지 않는다.

- target/orientation/distance를 함께 보간하고 shortest-path quaternion을 사용한다. 각도·거리 한쪽만 순간 이동시키지 않는다.
- 첫 경맥 선택은 경맥 전체가 패널에 가리지 않는 구도로 필요한 만큼만 조정한다. 가까운 혈 선택마다 정면으로 리셋하지 않는다.
- 선택 점이 화면 안에 충분히 보이면 카메라는 고정한다. 화면 밖/가림이면 필요한 최소 pan/회전/줌을 적용한다. 사용자가 화면 맞춤을 누르면 전체 framing을 명시적으로 수행한다.
- 따라보기는 흉부→위팔→아래팔→엄지처럼 관련 구간별로 이동한다. 작은 점마다 크게 확대/축소하거나 앞뒤를 왕복하지 않는다. 번호 순서와 별도의 관찰 구간 데이터를 사용한다.
- 드래그·휠·터치·카메라 키 입력은 자동 진행과 복귀 이동을 취소한다. 종료/수동 중단 후 사용자가 만든 시점을 되돌려 빼앗지 않는다. 자동 정상 종료 시 복귀 여부는 기존 AC2 정책과 일치시켜 회귀 검사한다.
- 시각 전환 초기값은 짧은 fade 약 150–220ms, camera easing 약 450–750ms에서 실제 화면으로 조절한다. 이는 애니메이션 길이이며 task 실행 제한과 무관하다. reduced-motion에서는 긴 이동·점멸을 없애고 즉시 또는 짧은 전환을 사용한다.

### 점·경로·면

점은 화면 확대 정도에 따른 읽기 쉬운 크기를 유지하고 선택 점만 은은한 외곽 halo로 강조한다. 미세한 점의 hit area를 확대하되 인접 점 선택이 뒤섞이지 않게 한다. halo는 치료 반경이 아니다. 전체점에서 매 점의 이름을 DOM에 띄우지 않고 선택/주변 주요 label만 배치한다. label 축약과 실제 점 삭제를 혼동하지 않는다.

후면 점이 몸을 뚫고 전면에 모두 보이지 않게 depth를 적용한다. 선택 점이 가려지면 짧은 안내/선택 맞춤으로 찾게 한다. 눈·입 안·회음 등 특수 위치를 외피 위로 옮겨 보이는 척하지 않는다. 자료와 지원 표면이 없으면 해당 위치를 미지원으로 설명한다.

경로는 표면/분지에 맞는 구간 데이터로 만든다. 번호 순서만 직선으로 연결해 팔과 몸통 사이를 관통하면 실패다. 경로를 드러내는 효과는 shader/progress 또는 기존 geometry 범위로 처리하고 매 frame geometry를 다시 만들지 않는다. 체표 학습 연결선과 내부 경맥 주행 주장은 구분한다.

색 영역은 공유 carrier의 부위 face mask로 인체와 같이 회전한다. 점·경로가 면보다 잘 읽혀야 하고 원래 근육 윤곽을 덮어버리면 안 된다. 낮은 alpha와 부드러운 경계는 디자인 값이며 근거의 불확실성이나 치료 강도가 아니다. 선택 영역은 옅은 면+경계, 전체 비교의 나머지는 윤곽 위주로 표시해 색이 진흙처럼 섞이는 것을 피한다. 색만으로 구분하지 않고 명칭/선택 강조를 제공한다.

carrier가 여러 patch라면 seam·normal·depth bias를 검사한다. z-fighting·떨리는 경계·회전 시 깊이 순서 뒤집힘·인접 손가락으로 mask가 번지는 현상은 수정한다. 원래 근육 material을 영구 바꾸지 않으며 영역 raycast가 기존 해부 구조 클릭을 가로채지 않는다.

## 4. 실제 화면 인수 시나리오

각 task는 자신이 바꾼 항목을 구현 직후 검사한다. AT28은 전체 회귀이며 최초 UX 검사가 아니다.

| ID | 조작 | 합격 기준 | 주 담당 |
|---|---|---|---|
| G1 | 해부 관찰→경혈→폐경 오른쪽 | 같은 모델/배경/레이어 유지, 필요할 때만 사선 framing | AT6·7 |
| G2 | LU1→LU9→LU11→왼쪽 전환 | 선택·이름·side 일치, 패널 가림/과도 줌 없음 | AT6·7 |
| G3 | 따라보기 중 드래그·휠·터치·종료 | 자동 카메라/진행 취소, 뒤늦은 복귀 없음 | AT7 |
| G4 | 빠른 경맥/side 선택, 로딩 중 OFF/ON | 마지막 요청 적용, 이전 점 잔상/카메라 재시작/누수 없음 | AT7·21 |
| G5 | 390px에서 카드 펼침/접힘·점 선택 | 선택 점과 주변 landmark가 가시 영역에 남음, 터치 목표 약 44px | AT7 |
| G6 | 키보드·reduced-motion·해부 모드 복귀 | focus 순서/탈출 가능, 불필요한 이동 없음, 기존 선택/레이어 보존 | AT7 |

AT21 합격이 첫 종단 간 그래픽 기준점이다. 실제 폐경 점/카드/따라보기와 색 면이 함께 동작해야 한다. 이후 AT8–18은 해당 경맥 데이터와 특수 구간 화면만 추가 검증한다. 새 데이터가 공통 렌더링 결함을 드러내면 공통 코드에서 고치며 경맥별 예외 컴포넌트를 쌓지 않는다.

## 5. 성능과 저장

자료 전처리는 offline. 단일 공유 overlay/controller, carrier manifest, 위치 compiler, mask 편집 방식만 둔다. 점은 공유 geometry/instancing, 영역은 공유 topology와 compact index/weight, label은 화면에 필요한 일부만 사용한다. UI 상태 변경 때 인체 전체를 재생성하지 않는다. 같은 camera session/update clock을 사용하고 OFF 상태에서 매 frame 전체 표면을 탐색하지 않는다.

기존 20MiB overview / 96MiB geometry / 1M active triangles / 8MiB chunk 예산을 유지한다. 전체 carrier를 초기 JS/overview에 통째로 넣지 않는다. 경혈 진입 시 기능 모듈을 lazy load하고 부위/경맥 자료는 cache·취소·해제를 공통 경로로 처리한다. AT29가 수치 검증을 종합하지만 AT3·21에서도 추가 bytes/triangles/draw calls를 확인한다. 현재 장치의 측정 조건·전후 결과를 적고 근거 없는 FPS 보장은 하지 않는다.

보고서·원문·실패 이력은 work/ 또는 source 저장소에 유지하며 learner 배포 import에서 분리한다. 기록이 많다는 이유만으로 앱이 모두 로드하는 구조를 만들지 않는다. private 교재는 별도 승인 없이 배포하지 않는다.

## 6. 품질·범위 표시

361개 명칭 원장, 목표 670개 side instance, 실제 표시 가능 위치, 교육용 개략 위치, 기준 구조 검증, 교재 설명, 교수 검토, 공개 재배포는 서로 다른 계수다. source-only 및 실제 위치 실패를 이름만 바꿔 합격시키지 않는다. 반대로 AI 작성/교수 미검토/과거 미승인이라는 이유만으로 근거를 확인한 로컬 교육용 구현을 영구 차단하지 않는다.

사진의 색 면은 표현 참고다. 12경근/체표 학습 영역/임독맥 강조 면/신경 지배/피부분절을 동일한 해부 경계로 합치지 않는다. 이 계획은 학습용 위치·경로·면이며 진단·치료·자침 방향/깊이 시뮬레이션을 추가하지 않는다. 새 임상 내용의 사실 확인은 해당 자료 작업에서 일차 자료로 수행한다.
