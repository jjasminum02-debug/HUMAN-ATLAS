## 1. 이번에 확인한 사실

## 3. 엑셀을 정답으로 복사하지 않는 반영 계약

원본 파일명: `근육-기시정지-신경-작용-정리.xlsx` (실제 Downloads 경로의 NFC/NFD 차이를 정규화해 찾기).

SHA-256: `8e10e00e76f5da8e6d1be6a0f9dcab6039d9a3f81d8a3808c0fe28545802ab3c`.

T81에서 한 번 import하여 원본 hash·시트·행·열, 원문/정규화 후보/검증된 claim을 분리한다. 원본 및 전체 사적 표를 Git·웹 public·bundle에 복사하지 않는다. local ignored cache에 source staging을 두고 저장소에는 비민감 검증 메타데이터와 공개 근거로 독립 확인한 필요한 학습 overlay를 둔다. 공개 재배포 허가를 추정하지 않는다. T83은 이 staging과 검증 record를 재사용한다. 원본 hash가 달라지면 차이 검토 후 새 revision을 만들며 이전 검증을 무조건 재사용하지 않는다.

### 항목 매핑

- workbook row → 기존 canonical/TA2 target을 stable ID로 연결. 순서나 이름만으로 ID를 새로 발급하지 않는다. 같은 이름의 손/발 근육, 근육 전체/갈래/힘살, 좌우 미지정 행을 별도로 처리한다.
- `exact_match / part_of / one_to_many / ambiguous / out_of_scope / unmatched`를 근거와 함께 기록. 하나의 행으로 양측 mesh가 검증됐다고 세지 않는다. ambiguity를 자동 first match로 해소하지 않는다.
- workbook의 8개 영역은 원본 메타데이터다. 제품의 12부위·복수 소속을 대체하지 않는다. 엑셀에 없는 기존 target도 전체 조사 목록에 남긴다. 엑셀에만 있는 항목은 명시적으로 scope와 대조한다.
- TA2는 명칭/분류 근거이지 기시정지·작용·신경 전체의 독립 정답 자료가 아니다. 기존 verified claims가 있으면 exact concept/field/source를 확인하고 재사용하여 중복 조사를 줄인다.

### 검증 순서와 완료 기준

1. T81 첫 내부 단위는 `근육표` **6, 12, 22, 23, 44, 133, 139, 229, 186, 246행**. 얼굴 신경 가지·고유감각/운동 구분·근육 부분·손/발 동명어를 포함한 위험 표본 10개다. parser/identity/claim 검증 경로를 시험하는 단계이며 전체 257행 합격이 아니다.
2. 기시 D열·정지 E열·운동 F열·감각 G열은 claim별로 공신력 있는 해부학 교육 원문/기관 자료/원 연구를 확인한다. 기본적으로 서로 독립적인 2개 자료 또는 이미 동등하게 검증된 기존 claim을 대조한다. 복제 사이트 두 개를 독립 근거로 세지 않는다. 한 자료뿐이면 `single_source`, 상충하면 `conflict`, 확인 불가면 `unverified`를 보존한다. 기본 조사 작업을 사용자에게 넘기지 않는다.
3. 명칭과 기시정지 전체는 T81/T82의 필수 범위. 짧은 신경란은 검증된 수준까지만 쓴다. 신경 가지/신경근 범위의 불확실성 때문에 나머지 구조 카드까지 막지 않는다. 신경 연구 후반에 넘길 unresolved 관계도 누락 없이 목록화한다.
4. T83은 H열과 엑셀 밖 전체 근육의 작용을 동일 방식으로 검증한다. 작용·고정 조건·갈래 차이를 분리한다. 한글 정규화는 정확성 검증을 대신하지 않는다.
5. claim record는 적어도 target/field/source locator/확인일/상태/짧은 합성 설명/변경 이유를 담는다. 내부 진행표는 `총 대상 / 검증 / 단일 근거 / 충돌 / 미확인 / UI 채택`을 따로 센다. AI 검증과 사람 승인, 3D 좌표 검증은 각각 별도다.

이번 읽기에서 발견한 실제 검증 필요 사례: F23의 대광대근 신경 가지를 단일 가지로만 보편화하지 않는다. 해부 연구에서 부위별로 광대가지와 볼가지/연결망의 관여를 보고한다. 검증 전에는 확인된 상위 얼굴신경 수준까지만 짧게 표시하는 방식이 적절하다. 이것은 한 셀의 주의 사례이지 표 전체의 오답 판정이나 전수 검증이 아니다. [원 연구, PMID 37283304](https://pubmed.ncbi.nlm.nih.gov/37283304/).

**`운동신경 미확인`을 `별도 단일 감각신경 없음`으로 대신하지 않는다.** 감각의 독립 이름이 없다는 설명은 감각 입력 자체가 없다는 뜻도 아니다. 긴 일반론을 모든 근육 카드에 반복 노출하지 않고 감각·고유감각은 필요할 때 펼친다. 사용자 예시 문구도 해당 의미를 검증한 경우에만 쓴다.

H열 처리 시 한자가 든 괄호만 정확히 정리하고 조건·방향·의미가 들어 있는 괄호는 보존한다. 문자 제거 정규식 하나로 모든 괄호를 삭제하지 않는다. 원문은 source staging에 남긴다. runtime action 텍스트에는 CJK 통합/확장/호환 한자 문자 0건, 한글 용어/조건 유지, 대표 53개 변환 전후 대조를 자동/수동 검증한다.

## 4. T166 공통 관찰 UX와 상태 계약

### 선택은 두 의미로 분리

- `inspectionSelection`: 현재 표시 자격이 있는 실제 mesh/node를 관찰하기 위한 선택. source-only라도 실제 표시되고 localDisplay가 허용된 표면이면 선택 반투명/숨김/맞춤을 사용할 수 있다. 해부학 identity를 승인하는 행위가 아니다.
- `learningSelection`: 검증된 canonical binding이 있을 때만 이름·기시정지·기능 카드를 여는 기존 경로. source-only의 stableId를 만들어 넣거나 기존 `pickable`을 무조건 true로 바꾸지 않는다.
- 두 선택을 공통 controller의 명시적 상태로 연결하되 선택 하나마다 scene를 다시 만들지 않는다. source-only 선택 시 확인되지 않은 근육 이름/정보를 꾸며 표시하지 않는다. 필요하면 `선택한 구조`라는 작은 도구 제목만 표시한다.
- localDisplay held/default hidden/사용자 layer-off/지역 필터 밖의 표면은 hit 검사에서 제외한다. 앞쪽 source-only 때문에 뒤쪽 근육이 무조건 선택되는 것도 막는다. 현재 클릭한 표시 표면을 먼저 관찰 선택하고, 숨긴 뒤 다음 실제 표면을 선택할 수 있게 한다.

### 미니멀 도구

선택 시 기본 도구는 **주변 흐리게 / 선택 반투명 / 선택 숨기기** 세 개. 선택이 없으면 선택 도구는 접고 회전/확대/전체 복원만 필요한 위치에 남긴다. `보기 옵션`에는 선택만 보기, 선택 맞춤, 다중 선택, 단계적으로 숨기기, 되돌리기/다시 실행, 보기 복원을 배치한다. 모바일은 하단 접힌 도구로 같은 기능을 제공한다. task/JSON/source-only/검토 모드는 학생 버튼명이 아니다.

- `주변 흐리게`: 선택은 선명하게, 다른 표시 구조는 약하게. 기본 true는 기존 학습 선택 흐름 유지. 불투명 색상 약화로 충분한 경우 기존 공통 material 경로를 재사용한다.
- `선택 반투명`: 선택 표면 자체를 투명하게 하여 속 구조를 볼 수 있다. 1차는 명확한 on/off, 고정 alpha. 색만 옅게 바꾸고 반투명이라 부르지 않는다. 다중 겹침/뒤쪽 구조 깊이 표현을 실제 화면에서 확인한다.
- `선택 숨기기`: geometry 삭제가 아닌 사용자의 visibility override. 여러 번 눌러 표면을 벗겨 볼 수 있게 한다. 마지막 선택이 숨겨지면 유효한 카드/선택 상태를 정리하되 undo는 항상 남긴다.
- `단계적으로 숨기기`: 옵션에서 명시적으로 켠 동안만 클릭한 적격 표면을 숨기며 Esc/버튼으로 종료한다. 기본 탐색 클릭은 숨김이 아니다. 실제 절개/새 단면 geometry는 이번 범위가 아니다.
- `선택만 보기`: 되돌릴 때 이전 필터/레이어/개별 숨김을 복원. 카메라 자동 점프 없음. 맞춤은 별도 명시적 버튼.
- undo/redo와 `보기 복원`: compact한 표시 상태 delta만 보관하고 history 상한을 둔다. 복원은 사용자 숨김/반투명/일시 격리를 해제하며 source hold와 layer-off/지역 설정을 덮어쓰지 않는다. 새로고침 시 비영속 보기 override는 초기화하고 기존 region URL 계약을 유지한다.

효과 우선순위는 **권리·integrity/localDisplay → 지역/레이어 → 사용자 숨김 → isolate → 반투명/선택 강조**. 어떤 사용자 복원도 held를 노출하지 못한다. 로딩 도중/취소된 응답도 현재 override를 적용한다. 숨김/반투명 설정을 mesh 원본 데이터나 frozen manifest에 쓰지 않는다.

기존 단일 root/renderer/camera, resource queue를 재사용한다. 큰 anatomy 파일/검증 자료를 브라우저에 추가하지 않는다. `Set<nodeId>`/희소 opacity 상태와 공통 reducer/controller로 처리하고 구조별 컴포넌트·material 복제·task별 loader를 만들지 않는다. 투명도 변경으로 추가한 material은 재사용/해제하고 depthWrite/renderOrder는 실제 가림을 보고 검증한다. 첫 합격은 이 범위 전체에 대한 것으로, 단일 버튼만 만들고 complete라고 하지 않는다.

참고한 관찰 동작: Visible Body 공식 안내의 선택·숨김·다중 선택·Dissect·Isolate·되돌리기/복원. [공식 사용 안내](https://help.cengage.com/visible-body/student/visible-body/atlas-getting-started-android.html). UI 이미지/유료 모델을 복제하지 않는다. AR·퀴즈·투어·절단면·새 신경/경혈 레이어까지 T166에 넣지 않는다. 원래 앱의 모든 기능 동등성을 약속하지 않는다.

### T166 실제 검증

1440/1024/390px에서 전신 source-only와 canonical 근육/뼈 각각 선택 → 주변 흐림 반전 → 선택 반투명 → 숨김 → 뒤쪽 표면 선택 → undo/redo → 보기 복원을 확인한다. 다중 선택/격리 전후 상태, 단계 숨김 모드 종료, region 복수 선택, 레이어 off, held, 검색/카드, 키보드/터치, 카메라 연속성, loading 중 상태를 검사한다. renderer 1개/중복 node 0, 표시 변경 때문에 geometry 재취득 0. 20회 전환의 resource 안정성과 같은 조건 frame p50/p95를 비교한다. 22 성능 경보선/20% 악화 기준을 적용하고 실패는 숨기지 않는다. 핵심 reducer/정책 회귀와 typecheck/build, 실제 screenshots/console evidence를 남긴다.

## 5. T110 얼굴 우선, 전체 구조 gate 유지

T96 `region-target-packages-t96/T110.json`의 113개 exact target/owner/역사 hash는 그대로 둔다. work-order overlay만 만들어 표정근 관련 target을 먼저 처리한다. 첫 단위는 그 subset에서 최대10개 target을 정확히 동결한다. 이마·눈둘레·입둘레·광대·볼·코 주위 필수 표면과 양측 상태를 target별로 대조한다. 표정근을 공개 UI 하위 카테고리로 추가하지 않는다.

실제 객체/mesh datablock/경로/hash/collection ancestry/전체와 부착부/side/units/rest pose를 확인한다. 기존 T97 local archive/index와 읽기 전용 parser, T98–100에서 검증된 공통 방법을 활용하되, 얼굴용 실제 correspondence/landmark/좌우/크기/잔차/표면 겹침을 독립 검증한다. 다른 source의 geometry라는 이유로 광배근 정합 결과를 그대로 복사하거나 mirroring으로 양측을 꾸미지 않는다.

권리와 좌표 적격성이 충족된 실제 표면을 같은 scene에 통합한다. source-only 관찰은 T166 경로, 정확한 canonical 이름/카드는 항목별 binding 검증 후 연결한다. 저장된 객체 이름 목록/웹 이름 검색/목표 표만으로 얼굴 구조 구현을 완료하지 않는다. 실제 source 부재/권리 미확정이면 필수 누락으로 유지하고 마지막으로 확인한 구체적 파일·필요한 조치를 남긴다. 같은 입력을 재검색하며 task를 늘리지 않는다.

얼굴 정면·좌우측면·비스듬한 각도와 근접/전신에서 표면의 실제 존재, 가림, 양측, 선택/hide/fade/복원을 확인한다. 입·눈 주위가 비어 보이면 어떤 필수 target의 부족인지 바로 대조할 수 있어야 한다. 기본 카메라와 위치만 바꿔 빈 부위를 감춘 것은 합격이 아니다.

**완성된 전신 구조 모델의 판정 시점은 T80 + T58 통과**다. T101–107 또는 T110 하나가 끝났다고 전신이 완성되지는 않는다. 필수 named muscle/side/part와 실제 표면/선택/세 이름을 전수 대조하며, 표정근과 광배근의 누락이 있으면 이 gate를 통과시키지 않는다. 정확한 완료 날짜는 현재 확보되지 않은 자산 검증이 끝나기 전 보장하지 않는다.

## 6. 얼굴 움직임의 명시적 제외

이번 사용자 요청의 `얼굴근육`은 **얼굴 표정을 만드는 근육**으로 적용한다. 머리 전체/씹기근/외안근/혀근육의 애니메이션까지 묵시적으로 제외하지 않는다. T110은 해당 subset의 exact target IDs/근거를 motion-policy overlay로 기록하고 T35가 동결한다. named muscle과 그 part/group의 포함 관계를 검토하며 region=head만으로 판정하지 않는다. 애매한 target은 보류하고 자동 제외하지 않는다.

- 구조·세 이름·기시정지·작용·짧은 운동신경: 다른 근육과 똑같이 필수.
- 애니메이션 상태: `deferred_by_user`, required=false. `unsupported` 자산 결함과 구별하며 완료로 세지 않는다.
- 버튼: 카드의 `움직임으로 이해하기` 위치는 유지하되 disabled/aria 설명으로 **현재 미지원**을 짧게 전달. 눌러도 재생 명령·로더·장면 전환을 실행하지 않는다. 작동하는 것처럼 보이는 무반응 버튼, 가짜 clip, 다른 근육 동작 대체는 금지.
- T35/T66/T47/T85: 전체 구조/설명 분모는 유지하고, required motion subset과 사용자 제외 목록을 별도로 전수 대조한다. `지원 + 명시 제외 + 미지원 = 전체 동결 대상`을 확인한다. 사용자 제외만 남아 있으면 개정된 motion gate의 합격은 가능하나 **모든 근육 애니메이션 완료**라고 쓰지 않는다. 그 밖의 필수 미지원은 계속 실패다.
- 신경 단계 시작 조건은 **개정된 필수 motion gate T85**이며 표정근의 명시적 제외는 신경 진행을 막지 않는다. 얼굴 신경/지배근 조사까지 제외한 것은 아니다.
