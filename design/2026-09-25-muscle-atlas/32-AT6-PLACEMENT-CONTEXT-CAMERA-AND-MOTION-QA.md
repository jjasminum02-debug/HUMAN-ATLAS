# AT6 연결 보완·경혈 문맥 카메라·움직임 품질 조사

2026-10-11 사용자 요청. 이 문서는 설계 정정이며 AT6 완료나 motion 수정 완료가 아니다. AT1–6 실제 보고서·코드·자료와 현재 localhost 화면을 확인했다. 기존 AT 순서는 유지하고 AT6 재개 및 AT7 인수 기준을 보강한다. 근육 변형은 별도 MV1(Luna Max 조사) → MV2(Sol High 수정) 흐름이며 자동 실행하지 않는다.

## 1. 현재 사실과 설계상 누락

| 작업 | 실제 산출물 | 여기서 완료되지 않은 것 |
|---|---|---|
| AT1 | 14경맥 361개 코드/명칭 원장, 계획 side instance 670개 | 좌표/표시 |
| AT2 | 근막·근육 외곽을 이용하는 교육용 체표 방법, 오른쪽 넙다리 표본 | 실제 전신 피부 |
| AT3 | 몸통·팔·다리 11개 chunk | 어깨/손목 등 열린 경계, 피부 지표 |
| AT4 | 세부 부위 72개 추가, 총 83개/813,096 bytes/40,520 triangles | 주름·점막 등 실제 미지원 영역 |
| AT5 | 명시적 landmark·비례 규칙 compiler 및 AI 작성/검토/권리 분리 | 실제 모델 landmark annotation |
| AT6 | 11혈 양측 22개 설명 카드와 learner 연결 | 실제 표시 위치 0/22, 필수 인수 실패 |

AT6 validation의 acceptancePassed=false, engineeringValidationPassed=true를 구분한다. partial은 부분 승인이 아니다. learner/lung.json의 projections=[]이고 카드를 눌러도 생성할 점과 카메라 overlay가 없다. 현재 실제 LU9 화면에서도 위치 표시 0/11을 확인했다. DEV 예전 proposal 화면은 이 learner 위치 완료와 다르다.

AT5 localLearnerEligible는 AI 작성/교수 미검토 자체를 차단하지 않는다. 현재 실패는 위치 관계·지표와 지원 표면 입력의 부재다. 그러나 설계도 문제였다. 기술 표면과 검증기를 만드는 일은 배정했지만 **실제 기준점을 작성하고 교육용 모형에 연결하는 일의 입력·산출물이 불충분**했다. 이를 AT6에서 완성해야 한다. 보고서/해시가 많아져도 실제 표시가 늘지 않으면 제품 진척이 아니다.

## 2. AT6 재개 방법 — 조사표를 실제 입력으로 바꾼다

AT1–5를 재실행하거나 전체 피부를 다시 만들지 않는다. AT6의 22개 remaining unit을 아래 세 종류로 나누고 담당 AI가 실제 입력을 작성한다.

1. 현재 뼈·근육·힘줄로 기준을 대조할 수 있는 항목: source triangle/barycentric, side, 정지 pose와 문헌 관계를 기록하는 annotation을 작성한다. 기존 source 이름 목록을 되풀이하는 것으로 끝내지 않는다.
2. 직접 피부 지표는 없지만 모델의 기준 구조와 문헌 관계로 교육용 표현이 가능한 항목: 실제 관찰한 지표와 AI가 작성한 모형상 지표를 분리하고 대응 과정·한계·표시 등급을 기록한다. 원본에 주름이 있다고 주장하지 않는다. '모형용 지표가 파일로 없으므로 불가'는 새 지표를 작성하지 않을 이유가 아니다. 교수 서명은 독립이다.
3. 실제 지지 표면이나 의미 있는 대응을 만들 수 없는 항목: source-bound 파생 patch를 필요한 구간에만 작성/등록하고 local frame·좌우·관통·연결을 검증한다. AT6의 손목 공백 등 소비에 필요한 국소 보완은 이 재개 범위에 포함한다. 전신 재조형은 제외한다. 끝내 필요한 자료가 없으면 정확한 항목과 시도 결과를 남긴다.

가장 근거가 충족되는 실제 혈 하나에서 `문헌 관계 → native 지표 → 파생 체표 → compiler → learner 점 표시`를 먼저 끝내고 같은 경로로 양측 22개를 처리한다. 성공 항목을 쓰지 않고 전부 unresolved로 다시 제출하는 일을 피한다. 문헌은 공식 표준/교재 등 일차 자료로 확인하고, 웹 snippet이나 bounds 비율만으로 좌표를 승인하지 않는다. nearest/raycast는 확인된 지표를 표면에 연결하는 수치 도구로는 사용할 수 있으나 위치 의미를 증명하는 근거는 아니다. 기존 금지 enum을 단순히 이름만 바꿔 우회하지 않는다.

기술 판정·교육용 모형 위치·정밀 취혈·교수 검토·공개 권리를 분리한다. 현재 schema로 정직한 모형용 지표를 기록할 수 없으면 해당 필드/판정과 회귀 검사를 최소 확장한다. 단순 전체 gate 해제나 missing=[] 조작은 금지한다. AT6 완료 기준은 양측 22개 실제 표시 그대로이며 이번 설계 변경으로 pass하지 않는다. 일부 표시 성공은 유효한 진척으로 보존하되 전체 완료와 구별한다.

## 3. AT7 — 점이 아니라 기준 구조까지 맞추는 카메라

현재 focusSection은 같은 구간 점들의 Box3에 작은 여백을 넣는다. 근육·뼈 landmark 범위를 사용하지 않는다. 별도 focus에는 LU1=.31m/LU9=.16m/기타=.07m 고정 거리가 있다. safeRect는 canvas 가장자리 여백만 계산한다. 또한 실제 점 클릭 callback은 select만 하고, 카드 버튼은 choose→focusSection을 호출한다. 입력 방식별 동작도 통일해야 한다.

### 데이터와 계산

공통 `ObservationContext`(명칭은 구현 시 기존 타입에 맞춤)를 경혈/side/기준 pose에 연결한다: point 위치, context source keys, 구조의 국소 구간/landmark bounds, preferred view normal, 최소 문맥 범위, 가림 고려 방향. 전체 긴 근육/노뼈의 bounds를 무조건 합쳐 팔 전체가 들어오는 것도 피한다. 필요한 것은 해당 혈 인근의 근육·힘줄 구간과 기준 뼈·관절이다.

선택 시 다음을 수행한다.

1. 선택 점 + 필요한 문맥 구간의 bounds를 구한다. 데이터가 없는 인접 구조를 가짜 bounds로 만들지 않는다.
2. 카드/상단바/하단 조작부와 실제 겹치는 영역을 제외한 가시 사각형을 계산한다. 이미 CSS로 분리된 패널은 중복 차감하지 않는다.
3. 현재 방향 및 제한된 후보 사선에서 문맥 bounds를 투영하고 가시성·화면 점유·가림을 평가한다. frame마다 전신 raycast하지 않고 선택/resize 시 계산한다.
4. 실제 fov/aspect와 문맥 크기로 거리를 계산한다. 점만 확대하거나 전신샷으로 후퇴하지 않는다. 초기 디자인 목표는 문맥의 긴 변이 가시 영역의 약 50–70%를 차지하는 중간 거리이며 부위별 QA로 조절한다. 이는 해부 수치가 아니다.
5. 이미 점과 기준 구조가 충분히 보이는 경우만 현재 구도를 유지한다. 점 한 픽셀이 frustum 안이라는 이유로 카메라를 고정하지 않는다. 아니면 target/distance/orientation을 함께 부드럽게 이동한다.

중부/운문은 가쪽 위흉부·어깨 주변, 척택은 팔꿈치와 상하 인접 구간, 태연은 손목과 아래팔 끝·엄지쪽, 소상은 엄지 말단과 손톱·인접 구조가 읽히는 구도를 지향한다. 이 예는 관찰 범위이며 새 혈위 좌표 승인이나 실제 없는 피부 구조 생성 지시가 아니다.

### 동작과 합격

카드/검색/실제 점 클릭 모두 같은 문맥 관찰 함수를 호출한다. 화면 맞춤은 경맥 전체, 선택 맞춤은 해당 문맥을 재사용한다. 사용자 orbit/wheel/touch는 즉시 자동 이동을 취소한다. 동일 side/같은 구간에서 불필요한 앞뒤 반전은 없다. reduced-motion·마지막 요청만 적용·단일 CameraSessions 원칙을 유지한다.

실제 점이 미확정이어도 **확인된 기준 구조 보기**는 독립적으로 개발할 수 있다. 이 경우 점/halo는 만들지 않고 '주변 구조' 관찰임을 구별한다. 이는 AT7 기술 개발의 대안이지 AT6 성공을 대신하지 않는다. 해부 표면에 붙지 않은 점을 보기 좋게 옮기거나 움직임 자세에 정지 좌표를 붙이지 않는다.

LU1/LU5/LU9/LU11 양측을 실제 390/1024/1440에서 검사한다. 가시 사각형 내 point/context projected bounds, 가림, 최소 주변 구조, camera before/after와 실제 screenshot을 남긴다. hidden 사용자 레이어를 몰래 켜거나 모든 근육을 지우지 않는다. 가려진 지표는 명시적 관찰 조작을 제공한다. UI 디자인 개편은 하지 않는다.

## 4. 근육 변형: 확인한 것과 아직 모르는 것

사용자 첨부는 대퇴직근 무릎 폄 시범의 준비 자세에서 표면이 활처럼 분리돼 보이는 결함 제보다. 대흉근은 추가 제보다. 이번 localhost에서 동일 넙다리곧은근 route/두 작용/무릎 asset 및 진행막대 0/50/100을 확인했지만 첨부의 정확한 시점·시각을 동일하게 재현 완료했다고 주장하지 않는다. 대흉근 전수 시각 검사는 아직 수행하지 않았다.

공통 author_t66_family_motion.deform은 pivot/axis/vertex weight에 따른 linear blend 또는 fractional rotation이며, 이후 접촉/ARAP/국소 표면 보정과 morph target을 생성한다. 이는 실제 근육 수축을 계산하는 생체역학 solver가 아니다. 원인 후보는 endpoint/weight field, 관절 pivot/경로, 원본→world 변환, 접촉 보정의 과도한 밀어냄, morph 보간 및 준비 자세/작용 방향 매핑이다. 사진만으로 하나를 확정하지 않는다. 특정 가중치 공식을 전부 교체하면 다른 부위를 망가뜨릴 수 있다.

현재 working tree motion-learning에는 asset record 1,160개, 고유 URI/hash 46개가 있다. 46개 실제 파일 hash는 등록값과 모두 일치했다. 이는 시각 품질 통과가 아니다. local delivery index는 74개 항목이며 역사/추가 경로가 섞였을 수 있으므로 MV1에서 learner generated runtime·실제 선택 조건과 연결해 조사 분모를 확정한다. 1,159개 binding_verified를 자연스러운 수축 합격으로 읽지 않는다.

### MV1 — Luna Max 전수 조사

현재 learner가 실제 재생할 수 있는 asset/clip/side/subject 매핑을 동결한다. 고유 hash+clip+적용 transform+재생 매핑으로 중복을 제거한다. 동일 파일이어도 다른 crop/context/side/역방향 재생이면 별도 사용자 흐름 검사가 필요하다.

공통 검사기로 rest·준비·중간·최대·복귀와 키프레임 사이를 검사한다. endpoint drift, transform 중복, 인접 bone/contact 관통, triangle 뒤집힘/급격한 면적·edge 변화, 실루엣 돌출, 이웃 근육과 분리, temporal pop, 원상복귀를 기록한다. 정상 근육의 형태 변화를 전부 오류로 판정하지 않으며, 전 부위에 하나의 볼륨 임계값을 강요하지 않는다. 열린 mesh의 signed volume도 물리 부피로 쓰지 않는다.

고유 clip 전수의 정면/측면/사선 contact sheet 및 전체 재생 시각 판정을 남긴다. 자동 수치만으로 자연스러움 pass하지 않는다. 분모 전체에 pass/fail/not_checked/error를 기록하고, not_checked를 통과에 섞지 않는다. 우선 대퇴직근과 대흉근을 확인한 다음 나머지 전체를 처리한다. 공유 자산은 한 번 평가하고 각 근육의 역할·강조·실제 작용 연결을 별도 대조한다. 새 생리학 주장에는 근거를 대조한다.

산출물은 versioned inventory, defects, 실제 frame evidence, 원인 후보별 grouped repair queue다. 원인마다 task 번호를 발급하지 않는다. Luna는 조사 도구와 evidence만 소유하고 기존 runtime/자산/사용자 WIP를 수정하거나 일괄 승인 취소하지 않는다.

### MV2 — Sol High 원인별 수정

MV1의 고정 queue에서 우선순위가 높은 **공통 원인 묶음 하나**를 선택한다. 대퇴직근/대흉근이 같은 원인인지 먼저 검증한다. 대표 사례에서 source endpoint·변형·bone 경로·접촉 보정을 고치고, 같은 알고리즘이 적용되는 자산만 일괄 재생성한다. 다른 원인은 remaining queue로 유지하고 자동 추가 task를 만들지 않는다. 반복 실행은 새 조사 없이 변경된 hash와 영향 범위만 검증한다.

시작부터 모두 FEM/새 rig 엔진으로 교체하지 않는다. 필요한 경우 부위별 가중치/경로 또는 pose corrective를 사용하되 source 부착·다관절 조건을 보존한다. 전체 mesh 단순 scale, 부풀림 감추기용 투명화, 임계값 완화, 동작 각도만 축소해 성공 주장, 근육을 숨기는 해결은 금지한다. 잘못된 수축/작용 설명도 함께 정정한다.

최종 emitted GLB를 실제 loader/controller에서 재생해 검증한다. authoring 중간 결과만 통과시켜서는 안 된다. 같은 카메라의 전후 화면, 전체 재생/중간 보간, 원상복귀, 양측, 주변 구조·권리·hash 보존과 비용 회귀를 남긴다. 해결한 queue 범위만 완료 처리하고 전체 수정 완료는 마지막 미해결이 없어야 한다.

## 5. 실행 경계

AT: AT6의 실제 지표/국소 carrier/위치 연결 → AT7 문맥 카메라 → 기존 AT20–22 조기 그래픽 검증 → 나머지 순서. AT7의 독립 기술 검사는 AT6 미확정 항목 때문에 영구 차단하지 않지만 사용자 요청 없이 자동 착수하지 않는다. AT6 acceptance/nextUnit은 이번 검토에서 바꾸지 않는다.

Motion: MV1 조사 → 사용자 확인 가능한 defect/repair queue → MV2 원인 묶음 수정. AT와 파일을 동시에 수정하지 않는다. 이번 턴에는 MV1/MV2를 실행하거나 다른 대화에 메시지를 보내지 않았다.

모든 실행은 작업 기준선·관련 검증·소유 변경만의 로컬 commit·다음 프롬프트를 남긴다. 원본/OpenSim_Models/T13 drafts/사용자 WIP 보존. push·배포·진단·치료·침 시뮬레이션 없음.
