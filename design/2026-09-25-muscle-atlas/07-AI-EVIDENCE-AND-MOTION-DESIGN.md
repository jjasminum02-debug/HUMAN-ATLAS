# R13 — AI 자료 검증, 근육 작용 설명과 움직임 학습

2026-09-26. 사용자 요청에 따른 설계 개정. 06의 12개 부위·다중 소속·근육/뼈 카드·세 이름 정책과 T15a–g 순서는 유지한다. 본 문서는 AI 자료 검증, 움직임, T16 이후 계획에 관하여 이전 문서보다 우선한다. 설계·예제는 런타임 구현이나 사람 승인 기록이 아니다.

## 1. 사용자가 근육 표를 대신 작성할 필요는 없다

근육의 이름·기시·정지·대표 작용은 AI가 원문을 찾고 대조하여 작성한다. 기존 T14b의 사람 검토를 모든 학습 콘텐츠와 개발의 필수 선행으로 둔 것은 개인 학습용 제품에 과도했다. 사람 검토 기록은 보존하되 일상적인 문헌 정리는 자동화한다. 인터넷 검색 결과를 그대로 정답으로 복사하는 것은 자동 검증이 아니다.

| 구분 | 기본 담당 | 통과 조건 | 사용자에게 넘기는 경우 |
|---|---|---|---|
| 세 이름, 기본 기시·정지, 작용 | AI 조사·구조화·재대조 | 실제 원문 locator, 개념/부분 구분, 조건·변이와 충돌 처리 | 강의 용어 선택 등 사용자 선호가 필요한 경우 |
| 뼈/근육 ID와 모델 연결 | 출처 crosswalk + 자동 검사 + 화면 검사 | 좌우·모델·실제 표지·원본 ID 일치 | 정체가 불명확하여 근거로 결정할 수 없는 경우 |
| 정확한 부착 footprint | 별도 모델 주석 제작과 검증 | 해당 모델에 대응되는 경계·좌표·해시·근거 | AI/도구로 해결 못 하는 위치 판단은 전문가 검토 후보로 남김 |
| 교육용 움직임 | 출처 기반 clip 제작 + 코드/화면 검사 | 움직이는 뼈, 방향, 고정 조건, 설명·표시의 일치 | 불명확한 관절 경로나 큰 형태 왜곡이 남을 때 |
| 전문가 검토 완료 표기 | 실제 검토자 | 실제 의견·범위·revision 기록 | AI가 사람 승인을 생성할 수 없음 |

필요한 사람 판단은 모든 표의 수기 확인이 아니라 해결하지 못한 예외 목록이다. 예외마다 이미 비교한 근거·엇갈리는 내용·현재 표시 정책·추천 후속 조치를 AI가 먼저 준비한다. 사용자는 자료를 제공하지 않아도 된다. 작년 근육학·골학 요약을 제공하면 강의의 범위와 명칭을 맞추는 별도 근거로 읽고, 외부 원문과 구분한다. 요약을 제공했다는 사실은 해부학적 승인이나 외부 업로드 허가가 아니다.

## 2. 한 개의 reviewed 값 대신 독립 상태

기존 canonical review 기록과 의미를 덮어쓰지 않는다. 새 AI evidence overlay와 learner projection을 만들고, T16에서 migration과 validator를 구현한다.

- evidenceState: unresearched / single_source / cross_checked / conflicted / unavailable.
- humanReview: 기존 상태 또는 null. AI 검사로 approved로 바꾸지 않는다.
- geometryState: absent / context / illustrative / model_validated. 정확한 부착 범위와 교육용 도식을 구분한다.
- motionState: absent / text_ready / clip_draft / educational_ready. 근육 문장 하나가 준비됐다고 clip을 ready로 만들지 않는다.
- publication: 교육용 표시 가능 여부와 그 이유. 환자 판단·임상 승인 필드는 이번 범위에 넣지 않는다.

기본 문헌 카드와 저위험 이름/기본 기시정지 퀴즈는 cross_checked 상태와 최신 claim hash를 기준으로 사용 가능하다. single_source도 권위 있는 직접 근거가 있으면 출처와 제한을 붙여 표시할 수 있으나 기본 퀴즈 정답에는 포함하지 않는다. conflicted 항목은 확정 단문 정답에서 제외하고 차이를 설명한다. 검사 수행·판정 기준의 공개와 검토 정책은 T36에서 별도로 정한다. AI 자료 대조를 사람 검토 완료라고 표시하지 않는다.

학습 화면에는 내부 상태 코드나 검토 큐를 상시 노출하지 않는다. 설명에 영향을 주는 차이만 짧게 쓰고, 출처 펼치기에서 확인 범위를 제공한다. 문헌 카드 사용에 별도 사람 이름 입력을 요구하지 않는다.

## 3. AI 문헌 작업의 실제 절차

1. 안정 ID, individual/group/part, 좌우/표준 변이, 조사할 필드를 고정한다.
2. 해부학 표준의 명칭 자료, 해부학 교재/대학 자료, 필요한 경우 연구 원문을 찾아 실제로 연다. 검색 snippet·AI 답변은 최종 근거가 아니다. 접근 실패하면 다른 원문을 찾고 실패도 기록한다.
3. 필드별 주장과 근거를 연결한다. URL, 판본, 절/표/그림/페이지, 접근일, 허용된 짧은 발췌 또는 원문 대조 메모, 원문 적용 범위를 저장한다. 단위·좌우·기시/정지를 뒤집지 않는다.
4. 다른 출처의 같은 필드를 대조한다. 같은 교재를 재인용한 두 사이트는 독립 근거 두 개로 세지 않는다. 문헌 두 개가 존재한다는 이유만으로 모든 필드를 일치 처리하지 않는다.
5. 원문을 다시 열어 한국어 요약이 해당 문장을 지지하는지 별도 검증 패스로 확인한다. 같은 모델의 재검토도 가능하지만 사람 검토나 독립 실험으로 부르지 않는다.
6. 일치/표현 차이/변이/실질 충돌/누락을 구분한다. 충돌하는 숫자나 부위는 평균 내지 않는다. 기본 해부학은 대표 설명과 변이를 함께 관리한다.
7. schema/reference/hash 검사, 이름 검색, 선택 ID 연결, 학습 표 렌더링을 검증한다. 모델 이름과 confidence 점수만으로 통과시키지 않는다.

결과 표: 구조 ID | 우리말명 | 한자어명(한글) | 영어명 | 기시 | 정지 | 작용과 조건 | 근거 locator | 일치/차이 | 남은 항목. 원문 장문을 복제하는 대신 짧은 자체 요약을 작성한다. 사람이 해야 하는 입력표가 아니라 AI가 완성해 제공하는 표다.

## 4. 선택과 흐리게 보기

부위 선택 → 근육/뼈 클릭 → 해당 카드가 기본 흐름이다. 근육을 선택하면 선택 근육은 선명하게, 다른 근육은 약하게 흐리게, 관련 뼈는 위치를 읽을 수 있게 남긴다. 소흉근처럼 깊은 구조는 이를 가리는 대흉근의 투명도를 더 낮춰 식별한다. 숨긴 구조를 몰래 다시 표시하지 않는다.

토글의 이름은 **주변 근육 흐리게**다. 기본 켜짐, 끄면 원래 가시성/색/투명도로 복원한다. 별도 **이 근육만 보기**는 선택 근육과 필요한 뼈만 남긴다. 근육 선택을 바꿔도 사용자가 토글을 끈 선택은 유지한다. 부위 변경 때 숨김 목록과 focus 강조를 혼동하지 않는다. 뼈 선택은 근육의 작용 카드를 재사용하지 않고 뼈의 표지·관련 근육 카드를 연다.

구현은 저장된 baseVisibility와 일시적인 selectionFocus를 분리한다. 흐린 구조가 포인터를 가로채는 문제, 선택 해제/뒤로가기/부위 변경/격리 해제의 복원을 회귀 검사한다. raycast에서 단순히 모든 흐린 구조를 제외하지 않는다. 현재 보이는 구조를 선택할 수 있고 선택 근육이 깊을 때는 목록·이름표로 접근 가능해야 한다.

## 5. 근육 카드와 버튼 문구

기본 카드 순서: 삼각근 같은 기본명 → 우리말/영어 → 위치·기시·정지 요약 → **이 근육이 하는 일** → **움직임으로 이해하기**.

버튼은 근육을 선택한다고 자동 재생하지 않으며 누르면 움직임 보기로 들어간다. 작용이 여러 개면 `앞으로 당기기 · 전인`, `아래로 내리기 · 하강`, `아래로 돌리기 · 하방회전`처럼 일상 설명과 용어를 한 줄로 고른다. 소흉근에서 세 작용을 한꺼번에 한 축 회전으로 합치지 않는다.

재생 화면에는 재생/멈춤, 진행 막대, 처음 자세, 느리게 보기를 둔다. `처음 자세`는 clip 시간·pose를 초기화하며 카메라를 강제로 되돌리지 않는다. 카메라 초기화는 별도다. 진행 막대는 수축력%가 아니라 시범 진행 정도다. reduced-motion 환경에서는 자동 재생 없이 처음/중간/끝 자세와 같은 설명을 제공한다. 학습용 설명에는 '교육용 움직임'이라고 간결히 표시한다.

설명은 용어 나열에서 끝내지 않는다. 위치 → 어느 뼈/표지를 어느 방향으로 당기는가 → 움직임의 이름 → 고정/자세 조건 → 이 장면에서 관찰할 부분으로 연결한다. 소흉근의 예제와 출처 대조는 examples/pectoralis-minor-learning-example.json에 있다. 실제 사용자 데이터가 아니라 설계 예제다.

## 6. 움직임은 정적 모델에 버튼만 붙여서 생기지 않는다

현재 두 GLB는 skins 0, animations 0, morph target primitive 0이다. ThreeViewer는 loaded geometry로 일반 Mesh를 생성한다. 따라서 새 rig/animation asset을 넣어도 지금 경로가 skeleton·node hierarchy·clip을 보존한다고 가정할 수 없다. 정적 loader와 별도로 animation-capable scene adapter를 T22에서 설계한다.

첫 목표는 **설명과 일치하는 교육용 3D 움직임**이다. 근육에 힘 수치를 넣어 결과 운동을 계산하는 생체역학 solver는 이번 목표가 아니다. 한 근육이 단독으로 관절 운동을 전부 만든다고 설명하지 않는다. 근육 역할은 action/context와 연결하고 협력근·고정 조건을 근거 있는 범위에서 표시한다.

| 표현 단계 | 사용 | 완성 주장 |
|---|---|---|
| 정적 모델+방향 화살표 | clip이 아직 없을 때 설명 보조 | 움직이는 3D 기능 완성이 아님 |
| 뼈 운동+단순 근육 경로 | 교육용 첫 clip, 근육 형태 단순화 표시 | 수축 조직의 사실적 변형·정량 해석 아님 |
| rig/skin/morph가 있는 근육·뼈 clip | 목표 학습 경험 | 검증한 pose와 범위의 교육용 재생 |

뼈는 근거 있는 관절 frame·pivot을 따라 움직이며 근육은 별도 변형이 필요하다. 선택 근육 전체를 줄여 늘리는 scale 효과만으로 기능을 구현했다고 하지 않는다. 리깅/weight/shape key를 자동 제작한 경우도 부착 끝점, 중간 pose, 관통·뒤틀림을 검사한다. 이 검사가 안 되면 해당 clip만 보류하고 정적 카드와 다른 작업은 계속한다.

소흉근 장면은 흉곽·늑골, 견갑골, 쇄골을 함께 고려한다. 견갑골을 고정된 단일 hinge로 처리하거나 상완골을 움직여 전인이라고 부르면 안 된다. 전인/하강/하방회전은 구분된 교육용 시범이며 정상 ROM·정량 활성도를 임의로 주장하지 않는다. 실제 운동 경로와 범위는 T28에서 근거와 제작 설정을 기록한다.

## 7. 데이터·코드의 분리

- MuscleAction: 기존 JointAction과 연결되는 muscle/part ID, target structure, action ID, 역할, 조건, plain explanation, claim/evidence IDs. 기존 schema를 폐기하지 않고 adapter/migration 결정.
- MotionDefinition: action/context ID, 좌우, 움직이는 구조와 고정 구조, frame/pivot, pose 범위의 근거, 단계별 관찰 설명. 유효한 limb/region 범위 명시.
- MotionAsset: asset hash/revision, rig/node map, clip name, duration, representation(illustrative_path 또는 rigged_mesh), 검증 상태, 라이선스, model/frame/pose 호환성. 빠진 자료를 null로 두며 fake ID를 채우지 않음.
- MotionSession: idle/loading/ready/playing/paused/error, time/speed, selection snapshot. 콘텐츠 데이터에 UI 상태를 저장하지 않음.
- Learner projection: 근육·뼈 카드와 작용 요약. React component에 해부학 문장·소스 표를 하드코딩하지 않음.
- 제작/검증: 로컬 자료 수집·변환·validator·review 도구. 학습자에게 모델 ID/JSON/내부 gate 입력을 요구하지 않음.

브라우저에서 매 클릭마다 LLM으로 설명이나 운동을 생성하지 않는다. 검증한 콘텐츠·clip을 배포 자산으로 읽는다. 현재 정적 웹 구조로 가능하며 당장 별도 서버를 도입할 필요가 없다. 향후 서버 필요성은 사용자 계정/공유 편집 요구가 생길 때 결정한다.

상태 전환 규칙: 부위·구조 변경은 이전 재생을 중단하고 늦은 응답을 무효화한다. 숨김/투명도 override를 복원한다. camera control과 animation loop를 중복 실행하지 않는다. clip 종료/오류/탭 비활성화/unmount에 pause·dispose한다. 동작 중 구조 클릭은 일단 멈추고 해당 카드로 전환한다.

기존 rest-pose 부착 annotation은 움직이는 동안 그대로 두지 않는다. 정확히 binding된 bone-local 표시는 같은 node transform을 따르고, skinned surface는 skinning 대응이 검증된 경우만 움직인다. 대응이 없으면 움직임 보기에서 숨기고 '부착 위치는 처음 자세에서 확인'으로 안내한다. 제작 모드의 주석 찍기는 rest pose에서만 허용한다.

## 8. 품질 확인과 진행 방식

테스트는 출처가 실제 문장을 지지하는지, 문장과 action ID가 맞는지, clip의 좌우/축/pose가 설명과 같은지를 나눠 본다. 합성 fixture는 loader와 상태 검증에만 쓴다. 실제 해부학 clip의 검증으로 대체하지 않는다.

화면 수용 기준: 근육/뼈 카드 일치, 다른 근육 기본 흐림과 원복, 깊은 근육 접근, 동작 선택별 설명 동기화, 처음/중간/끝 pose, 움직임 중 방향 전환, 빠른 부위 변경, 잔존 annotation 없음, 키보드와 390/1024/1440 화면. 프레임 시간/메모리/네트워크 자산 크기는 측정 장비와 함께 기록한다. 밝은 배경, 아이보리 뼈, 자연스러운 근육색과 절제된 강조는 사용자 참고 이미지의 방향을 따른다.

T15a–g 이후 T16–40을 독립 번호로 분리한다. 24개나 40개를 전체 프로젝트 완료 개수로 고정하지 않는다. 전신 자료/rig 배치는 실제 범위에 따라 T41 이후 번호를 발급하고 한 번에 하나씩 실행한다. 전체 순서·커밋·다음 prompt는 08에 있다. 경혈·MPS·Pro mode·환자 진단·치료는 여전히 범위 밖이다.
